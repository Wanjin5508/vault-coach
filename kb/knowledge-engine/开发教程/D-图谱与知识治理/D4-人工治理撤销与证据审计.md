# D4 人工治理、撤销与证据审计

## 学习目标

让概念确认、拒绝、合并、alias、手工关系等治理行为可追溯、可撤销、可与 Connector 边界兼容。

## 先理解

- 治理动作应是追加式 decision/event，而不是无法追溯地原地改一行；
- undo 不是删除历史，而是写一条反向决策并重新计算 effective projection；
- merge 需要 canonical ID、被合并 ID、原因、证据与回滚语义；
- 审计记录最小化保存 actor/context/time/revision/decision，不保存不必要原文；
- connector 模式中，Vault Coach 是 M3 决策权威；Engine 只同步并展示，不能抢写。

## Engine 落点

managed workspace 可以在 Workbench 提供治理操作；connector workspace 只读或通过明确的未来回传协议处理，首版不提供隐式双向编辑。所有 GraphProjection 标注事实来源与治理 revision。

## 动手练习

1. 为 confirm、reject、merge、undo 设计 decision schema；
2. 连续执行 merge → undo，验证旧引用恢复且不产生悬空边；
3. 在 Inspector 中点击 relation，展示证据与决策链；
4. 写权限测试，禁止 Agent/Connector 直接调用 confirmed 写入。

## 通过检查

- 用户能解释有效图为何包含/排除某关系；
- 撤销不会破坏 ID 或历史 Assessment；
- 治理权限与工作区 source mode 一致。
