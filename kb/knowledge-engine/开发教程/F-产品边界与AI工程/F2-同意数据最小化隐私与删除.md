# F2 同意、数据最小化、隐私与删除

## 学习目标

将隐私视为产品与数据模型的一部分：系统知道自己为什么持有每类数据，用户能控制进入、外发、撤销和删除。

## 先理解

- 同意应绑定目的、范围、时间和可撤销性，不是一个笼统“允许访问”；
- 数据最小化意味着检索只返回 top-K 摘录，Career Agent 只接收 Profile，不接收任意 chunk；
- secret 与内容分开：token/API key 使用安全引用或环境变量，日志不记录；
- 删除链路必须覆盖事实副本、向量、搜索投影、缓存、job 产物与 Profile，不误删外部源；
- 本地 loopback 不等于无需解释模型 endpoint 的数据外发。

## Engine 落点

Workbench 显示 workspace source mode、导入/同步范围、模型提供方、Profile consent 与删除影响。Connector 与 Career Agent 均依赖版本化授权 DTO；默认无遥测、无 LAN 监听、无自动上传。

## 动手练习

1. 设计 `ConsentV1`：purpose、grantedAt、scope、expiresAt、revokedAt；
2. 做一次 Profile 预览/发布/撤销测试，确认 Career Agent 无法越权检索 chunk；
3. 审查日志字段，删除 query 正文、embedding、密钥与思维链；
4. 执行 workspace delete，检查所有派生数据清理并生成可读确认。

## 通过检查

- 用户能在操作前看到数据类别和目的；
- 撤销与删除有实际数据库/索引验证；
- 跨产品协同不等于共享数据库访问权。
