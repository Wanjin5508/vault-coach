# E2 进度、取消、重试与错误模型

## 学习目标

为长任务建立用户可理解、程序可处理的生命周期，而不是只显示“加载中”。

## 先理解

- 进度应表示可验证工作单位，如 `processedChunks/totalChunks` 和阶段，而非虚假的百分比；
- cancel 是协作协议：请求取消 → worker 在检查点发现 → 停止后不发布结果 → 标记 cancelled；
- retry 只用于暂时错误，并有最大次数、退避、错误分类和可见原因；
- `failed` 是最终失败，`stale` 是输入 revision 已过期，二者不应混同；
- 错误模型分为用户可操作摘要、机器 error code、内部诊断 detail 三层。

## Engine 落点

Job Inspector 显示阶段、输入 revision、进度、attempt、错误摘要和 cancel 按钮。模型速率限制、临时网络问题可 retry；schema 不合法、权限拒绝、过期 revision 必须快速失败或 stale。

## 动手练习

1. 为 embedding job 设计阶段：queued → reading → embedding → indexing → succeeded；
2. 在每批 chunk 后检查 abort signal，取消后验证无 effective 发布；
3. 模拟 429/503 与 400/401，验证 retry 分类不同；
4. 让 GUI 轮询/订阅状态但不传输整份向量或图。

## 通过检查

- 用户知道任务在做什么、能否取消、失败后该做什么；
- 失败没有被无限重试掩盖；
- 取消不会留下错误的完成状态。
