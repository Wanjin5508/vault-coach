# B4 事实源、派生投影与数据删除

## 学习目标

区分“用户知识事实”“Engine 副本”“索引缓存”“模型候选”，并为每种数据规定删除与恢复路径。

## 先理解

- 事实源回答“什么可以被权威修改”；派生投影回答“什么可以随时重建”；
- `managed` workspace 的导入 revision 是 Engine 训练事实，但仍只来自用户明确导入；
- `connector` workspace 中 Vault 的 Markdown、M2/M3 决策和插件 Assessment 是权威，Engine 只读其版本化副本；
- embedding、ES projection、缓存、推荐和 Agent draft 都不能自动升格为事实；
- 删除设计必须先列数据清单：主记录、chunk、向量、job、索引、备份、审计各如何处理。

## Engine 落点

`workspace.source_mode` 是策略开关。删除 managed workspace 清除其本机副本与派生数据；删除 connector 副本不删除 Vault；撤销 Knowledge Profile 只影响 Career Agent 授权数据。GUI 必须显示每个动作“会删除什么、不会删除什么”。

## 动手练习

1. 写一张数据所有权表，列出 content、concept、relation、assessment、embedding、job、profile；
2. 为 workspace deletion 写集成测试，验证向量/投影同时清理；
3. 设计 connector 的“断开但保留副本”和“断开并删除副本”两个动作；
4. 用匿名数据演练从事实表重建全部索引。

## 通过检查

- 没有一类数据的所有者、删除语义或恢复方式是模糊的；
- 不存在 Engine 写回 Vault 的旁路；
- 用户能在 GUI 中理解并确认破坏性操作。
