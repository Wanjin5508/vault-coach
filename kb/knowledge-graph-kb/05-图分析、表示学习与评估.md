# 05 图分析、表示学习与评估

## 1. 图分析的三类问题

| 类别 | 问题 | 常用方法 |
| --- | --- | --- |
| 节点重要性 | 谁是关键实体？ | degree、PageRank、betweenness |
| 社群与结构 | 哪些实体形成群组或桥梁？ | Louvain、连通分量、k-core |
| 路径与相似性 | 两者如何关联？ | 最短路、随机游走、共同邻居 |

算法输出是对给定图快照的计算结果，不天然等于业务真相。比如 PageRank 高说明链接结构中的中心性，不代表权威性或质量。

## 2. 表示学习：把结构映射到向量

知识图谱嵌入尝试让实体和关系在向量空间中保留结构规律。典型打分形式是：

\[
score(h,r,t)=-\|\mathbf{h}+\mathbf{r}-\mathbf{t}\|
\]

它可用于候选补全、相似实体和下游分类，但有三个硬边界：

1. 训练数据中的偏差会进入向量；
2. 得分高不是事实证明；
3. 训练/索引/模型版本变化会使近邻结果变化。

## 3. 文本 embedding 与图 embedding 的协作

文本向量回答“内容像什么”；图向量或路径回答“关系上像什么”。好的 Knowledge Engine 会先按权限与实体约束缩小集合，再做文本或向量召回，最后用图关系重排和证据验证。

## 4. 评估设计

- **抽取/链接**：精确率、召回率、F1，按实体类型和来源分层抽样。
- **检索**：Recall@k、MRR、nDCG，以及有无证据、权限正确率。
- **问答**：答案正确、引用正确、不可回答时是否拒答。
- **图算法**：与业务标签、人工评估或未来窗口对照，避免把训练数据当测试数据。

必须使用时间切分和实体切分，避免同一实体的近重复记录同时出现在训练集和测试集。

## 5. 从分析回到产品

将算法结果写回图时，应标记为 `derived` 或 `predicted`，并记录任务、输入快照、参数、阈值和过期时间。这样推荐、风险分和社群标签才能被复现、解释和撤销。
