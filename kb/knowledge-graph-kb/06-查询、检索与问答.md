# 06 查询、检索与问答

## 1. 查询范式不是竞争关系

| 范式 | 输入 | 最适合的工作 |
| --- | --- | --- |
| 图模式查询 | 节点、边、谓词、过滤器 | 多跳关联、路径、权限继承 |
| 关键词检索 | 词项、短语、过滤器 | 标题、正文、精确术语召回 |
| 向量检索 | 查询 embedding、过滤器 | 同义表达、语义相近内容 |
| 规则/推理 | 事实加规则 | 可解释派生、合规判断 |

同一个问题可以先用关键词/向量获得文档或实体候选，再通过图模式验证关系和权限。不要把向量相似度当成关系事实，也不要让多跳遍历承担全文召回。

## 2. SPARQL 与 Cypher 的思维方式

SPARQL 在 RDF 三元组模式上做匹配：

```sparql
PREFIX schema: <https://schema.org/>
SELECT ?paper ?title WHERE {
  ?paper a schema:ScholarlyArticle ;
         schema:author ?author ;
         schema:name ?title .
  ?author schema:affiliation <https://example.org/org/acme> .
}
LIMIT 20
```

Cypher 在带标签的属性图上描述路径：

```cypher
MATCH (a:Author)-[:AFFILIATED_WITH]->(:Organization {id: $orgId}),
      (a)-[:AUTHORED]->(p:Paper)-[:ABOUT]->(:Topic {id: $topicId})
WHERE p.publishedAt >= date() - duration('P2Y')
RETURN p.id, p.title
ORDER BY p.publishedAt DESC
LIMIT 20
```

两者的共同核心是选择性：尽早从少量节点开始、尽早过滤、限制路径长度，并让索引支持入口条件。

## 3. 混合检索的可解释流程

```text
身份与权限过滤
  → 关键词/向量召回各自 Top-K
  → 用实体识别和图约束扩展/过滤
  → 按统一排序策略融合
  → 取证据片段，生成带引用的回答
```

融合不能直接比较不同系统的原始分数。一个稳健的起点是 Reciprocal Rank Fusion（RRF）：

\[
RRF(d)=\sum_i\frac{1}{k+rank_i(d)}
\]

它只使用各召回器的名次；之后可在标注数据上学习重排模型。无论如何，响应中都应返回实体 ID、关系路径、证据片段和索引/图谱版本。

## 4. 图增强问答

图增强 RAG 的核心不是“把整张图丢给模型”，而是受控子图检索：

1. 将自然语言解析成实体、关系和时间/权限约束。
2. 从受索引支持的种子实体出发，限制跳数和边类型扩展子图。
3. 选择最短/最高置信的证据路径，回到原始文本核验。
4. 生成答案时引用证据；若图或证据不足，明确说明未知。

这与只按文档块向量化的 RAG 相比，多了一层实体消歧、结构约束和可解释路径，但也多了抽取错误、模式演化和时效治理成本。

## 5. 查询安全与可观测性

- 限制可变长度路径的最大跳数与返回量，防止指数扩张。
- 对用户输入使用参数化查询，避免注入。
- 在索引前或查询计划中施加租户/ACL 过滤；结果后过滤不安全。
- 记录 query template、执行计划摘要、延迟、候选数、截断原因与版本。
