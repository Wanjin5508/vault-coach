# 02 语义表示与本体工程

## 1. RDF：可交换的断言模型

RDF 用三元组表示断言：

```turtle
@prefix ex: <https://example.org/kg/> .
@prefix schema: <https://schema.org/> .

ex:paper-42 a schema:ScholarlyArticle ;
  schema:name "Graph systems"@en ;
  schema:author ex:person-li .
```

`ex:paper-42`、`schema:author` 都是 IRI；文本字面量可带语言或数据类型。RDF Dataset 还能用命名图隔离源、版本或权限边界：`GRAPH <urn:source:crossref:2026-01> { ... }`。

## 2. RDFS 与 OWL 的层次

| 层 | 提供的表达力 | 例子 |
| --- | --- | --- |
| RDF | 资源及二元断言 | `论文—作者→研究者` |
| RDFS | 类、子类、属性层级、域和值域 | `作者 ⊆ 人` |
| OWL 2 | 等价、互斥、基数、限制、可推导类别 | `教授 ≡ 人 ∩ 任职于某大学` |

本体（ontology）不是数据库表结构的同义词。它描述一个领域的概念、关系与约束意图，使不同系统把同一术语理解为同一事物，或明确它们的差异。

## 3. 从问题到最小可用本体

建议采用“问题驱动的最小承诺”：

1. 写 10–20 个能力问题（competency questions）。
2. 列出回答问题所需的类、关系、词表和标识符。
3. 复用已有词表；仅为本领域缺口新建术语。
4. 给每个类、属性写自然语言定义、范围、示例和负责人。
5. 以实例数据和查询测试，再演化版本。

例如问题“某机构近两年发表了哪些关于图推理的论文？”要求 `Organization`、`Paper`、`Topic`、作者/隶属关系和日期；它不要求先定义完整的学术世界。

## 4. 开放世界与封闭世界

语义网的经典语义通常采用**开放世界假设**：没有看到 `A 不是 B`，不等于 `A 是 B`，也不等于 `A 不是 B`。数据库查询和业务校验常接近**封闭世界假设**：表中不存在就视为不存在。

这一区别决定工程策略：OWL/RDFS 适合表达可推出的语义；“每篇论文必须有标题”“员工号必须唯一”应交给 SHACL、应用规则或数据库约束验证，而不要误以为本体声明自动完成数据质量治理。

## 5. 对齐、映射与版本

异构系统最难的是语义对齐。`author`、`creator`、`writer` 可能相同也可能不同。映射应带方向、版本和适用范围：

- `exactMatch`：只有经过严格审核时才使用；
- `closeMatch`：近似对应，不应自动合并 ID；
- 子类/子属性映射：保留更细粒度的一侧；
- 变换规则：记录字段拼接、单位换算和损失。

任何词表升级都要保证旧 IRI 的兼容、废弃说明和迁移计划。继续阅读 [[03-推理、约束与不确定性]]，学习如何安全地使用这些语义。
