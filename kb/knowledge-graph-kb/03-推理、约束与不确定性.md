# 03 推理、约束与不确定性

## 1. 推理回答“隐含了什么”

给定显式事实和规则，推理可以产出可解释的派生事实。最常见的 RDFS 例子：

```text
论文 P 的作者是 A
作者是 人 的子属性/范围约束
--------------------------------
A 是 人
```

更常用的模式包括子类传递、子属性传递、领域和值域推断，以及受控的规则链。每条派生边都应保存其规则、输入事实版本和计算时间。

## 2. 三种推理部署方式

| 方式 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| 物化（forward chaining） | 预先写入派生事实 | 查询快 | 数据变更时要重算/失效 |
| 查询时推理（backward chaining） | 查询展开规则 | 数据冗余小 | 查询慢、优化更难 |
| 混合 | 高频规则物化，其余查询时计算 | 平衡 | 需要明确边界 |

生产系统常把“是否为高风险客户”这类会随数据变化的派生结果作为物化视图，并用变更事件驱动增量重算。

## 3. SHACL：把形状当作可执行数据契约

SHACL 用 shapes 约束 RDF 数据。它回答“这批数据是否满足业务形状”，而不是“从逻辑上是否可推出”。

```turtle
ex:PaperShape a sh:NodeShape ;
  sh:targetClass schema:ScholarlyArticle ;
  sh:property [
    sh:path schema:name ; sh:minCount 1 ; sh:datatype xsd:string
  ] ;
  sh:property [
    sh:path schema:author ; sh:minCount 1 ; sh:class schema:Person
  ] .
```

把验证输出当作数据产品：记录 shape 版本、违反项、严重程度、来源批次和修复状态；不要只在日志中打印错误。

## 4. 不确定性与冲突

模型抽取得到的“候选关系”不应直接覆盖权威事实。推荐四层：

```text
source record  →  evidence span  →  candidate assertion  →  approved canonical fact
```

候选层保存模型、提示词/模型版本、置信度、原文偏移和抽取时间。融合规则可根据来源信誉、时间、字段一致性和人工审核来产生 canonical fact。置信度用于排序与审核优先级，不能把它当作概率真值，除非经过明确校准。

## 5. 规则与机器学习的边界

- 规则：透明、稳定、适合合规约束和已知业务逻辑。
- 链接预测/分类模型：擅长从模式中提出候选，必须保留阈值、离线评估和人工闭环。
- 大语言模型：适合抽取、归纳、解释和交互，但输出必须回链到证据与结构化验证。
