# 04 知识获取、融合、质量与治理

## 1. 构建流水线

一个可运营的图谱流水线通常不是“ETL 后导入”这么简单：

```text
采集 → 解析/标准化 → 实体识别 → 候选关系抽取 → 实体链接
   → 验证 → 融合/发布 → 索引构建 → 监控与回填
```

原始文件、解析结果、候选断言、规范事实和索引应有各自的版本。任何下游结果都要能追溯到输入批次和处理程序版本。

## 2. 实体解析与实体链接

实体解析（entity resolution）判断两个记录是否代表同一现实实体；实体链接（entity linking）把提及连接到已知实体或外部 ID。一个可靠流程分为：

1. **Blocking**：用规范化名称、邮箱域、时间窗、地理位置等廉价键产生候选对。
2. **Matching**：用规则、特征模型或向量相似计算候选分数。
3. **Decision**：自动合并、待审核、拒绝三档；阈值随错误代价设置。
4. **Cluster 与审计**：保存合并理由与可拆分历史，避免错误合并不可逆。

不要只用 embedding 最近邻作合并决策：它适合召回候选，却容易把同名、近义但不同的实体合并。

## 3. 融合与来源优先级

同一属性冲突时，先定义策略再运行：权威注册源优先、较新有效时间优先、字段级可信度、人工覆盖、或保留多值。策略应该逐字段可配置，不能全局“最新覆盖”。

推荐把 `assertedBy`、`derivedFrom`、`extractedAt`、`validFrom`、`validTo`、`confidence` 和 `reviewStatus` 作为一等元数据。

## 4. 数据质量度量

| 维度 | 可操作指标 | 示例 |
| --- | --- | --- |
| 完整性 | 必填属性覆盖率 | 论文有标题和作者的比例 |
| 一致性 | 违反规则/shape 的数量 | 日期结束早于开始 |
| 准确性 | 标注样本精确率 | 实体链接正确比例 |
| 时效性 | 延迟、过期事实比例 | 源更新到图可查询的时间 |
| 可追溯性 | 有来源的断言比例 | 可回链原文的关系比例 |

质量看板应按数据源、实体类型、关系类型和版本切分。总平均数会掩盖某一关键源的退化。

## 5. 治理与安全

治理对象包括模式、词表、数据源、规则、模型、索引和访问策略。最小机制是：数据所有者、变更评审、血缘目录、保留/删除策略、字段分级、审计日志和回滚。

在包含个人信息或商业敏感信息时，检索过滤必须在召回阶段执行；“先召回再在前端隐藏”会泄露候选和排序信息。下一章转向图算法和表示学习，它们会把这些受治理的数据转化为分析和检索能力：[[05-图分析、表示学习与评估]]。
