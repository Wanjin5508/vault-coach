# Vault Coach 测试参数与质量度量总览

## 1. 这套知识库解决什么问题

测试参数用于回答四类问题：功能是否正确、结果质量是否足够、速度和资源是否可接受、失败后是否安全恢复。一个参数只有同时写清 **定义、单位、统计范围、测试数据、运行环境和通过条件** 才能作为工程证据。

本专题覆盖当前插件以及已进入开发规划的能力。它不把规划中的指标伪装成已实现监控，也不把产品配置值误称为性能指标。

## 3. 三类数值必须分开

1. **产品配置值**：例如 `chunkSize=600`、`contextTopK=8`。它们控制行为，本身不证明质量。
2. **算法决策阈值**：例如掌握度 `0.85`、语义相似度 `0.86`。它们改变分类或排序结果，修改时必须做回归评估并更新算法版本。
3. **验收门槛**：例如 Recall@10 ≥ 0.80、查询 P95 ≤ 300 ms。它们用于 GO/NO-GO，必须在首次正式验收前冻结。

## 4. 当前证据状态

- 单元、集成、架构边界和构建检查已经存在，可通过 `npm test`、`npm run lint`、`npm run build` 执行。
- 里程碑 4 已建立三语检索基准和本地 Embedding 指标脚本，但协议仍为 `pending-owner-approval`。
- PDF 当前只支持文本型 PDF；OCR、表格和插图结构化抽取指标属于未来扩展。
- 本专题中的“建议门槛”是建立基线的起点，不能直接当成已有 SLA。

## 5. 新功能接入规则

每个新功能至少补齐：正确性指标、质量指标、性能指标、资源指标、可靠性指标、隐私检查、自动化层级和人工验收步骤。若指标无法自动化，要在 PR 中记录设备、样本和人工结论。
