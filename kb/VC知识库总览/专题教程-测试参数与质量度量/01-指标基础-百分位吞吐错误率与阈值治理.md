# 指标基础：百分位、吞吐、错误率与阈值治理

## 1. 延迟百分位

把 N 次耗时从小到大排序，Px 表示至少 x% 样本不超过该值。本项目脚本使用 nearest-rank：`index = ceil(N × x) - 1`。

| 指标 | 含义 | 用途 |
|---|---|---|
| P50 | 中位体验 | 判断典型速度 |
| P90 | 90% 请求以内的体验 | 日常交互门槛，能暴露一部分长尾 |
| P95 | 95% 请求以内的体验 | 当前 M4 查询延迟门禁 |
| P99 | 极端长尾 | 大样本、线上监控或压力测试 |
| Max | 最慢一次 | 定位异常，不能单独代表总体体验 |

P90 不是“平均值的 90%”。例如 100 次查询的 P90 是排序后的第 90 个耗时。少于 20 个样本时 P95 很不稳定；性能验收建议至少 30 次，重要路径建议 100 次以上。

## 2. 吞吐、错误率与资源

- **吞吐量**：`完成工作量 / 秒`。索引用 chunks/s，生成可用 tokens/s，文件扫描可用 files/s。
- **错误率**：`失败次数 / 总尝试次数`。同时按超时、网络、解析、模型、取消分类。
- **成功率**：`满足业务完成条件的次数 / 总尝试次数`，不能简单用 `1 - 崩溃率` 代替。
- **峰值内存**：运行期间最高 RSS、WASM heap 或 GPU memory。三者不能互相替代。
- **磁盘增量**：操作后派生数据字节数减去操作前字节数。
- **缓存命中率**：`无需下载或重算的命中次数 / 可缓存请求数`。

## 3. 冷启动、暖启动和稳态

- 冷启动：进程和缓存都未准备，包含资源发现、模型读取或下载；下载时间应单列。
- 暖启动：资源已在磁盘缓存，但运行时尚未加载。
- 稳态：模型或索引已在内存中，测量连续请求。

报告中不能混合三种状态。里程碑 4 的 `loadMs` 是运行时加载，查询延迟通过 2 次预热后测量 5 次；正式验收应增加重复次数。

## 4. SLI、SLO、SLA 与测试门槛

- **SLI**：观测量，例如查询 P95。
- **SLO**：团队希望达到的目标，例如桌面查询 P95 ≤ 300 ms。
- **SLA**：对外承诺及违约约定。当前本地插件没有对外 SLA。
- **测试门槛**：CI 或里程碑的通过条件，可以比 SLO 更严格以保留余量。

## 5. 阈值治理

1. 先定义用户场景和测试设备。
2. 冻结数据集、相关性标注和测量方法。
3. 在看 acceptance 结果前登记阈值。
4. tuning 集允许调参；acceptance 集只用于最终判断。
5. 阈值失败后修代码或记录 NO-GO，不能回改标签制造通过。
6. 每次修改数据、模型、分块、检索或硬件时记录可比较性。

建议统一使用 `pass / fail / pending / not-applicable`。缺少设备或样本属于 `pending`，不能记为 `pass`。
