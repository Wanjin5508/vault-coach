# 基准实验设计、结果模板与术语表

## 1. 一个可复现实验必须锁定什么

- git commit、未提交变更、Node/npm、Obsidian/Electron 版本。
- OS、CPU、内存、GPU、电源模式和执行后端。
- 数据集版本、样本数、语言/文档类型分层、tuning/acceptance 切分。
- 模型仓库、revision、dtype、哈希和运行时版本。
- 全部产品参数和算法阈值。
- 冷/暖状态、预热次数、测量次数、并发和 batch size。
- 原始逐样本结果、聚合方法、随机种子和失败样本。

## 2. 数据集规则

相关性标注至少两人复核一部分样本，并记录冲突解决方式。查询必须包含正常、边界、无答案、跨语言、PDF 噪声和长文档场景。合成集适合验证管线，不代表真实用户 Vault；真实集应去敏并得到授权。

不要让同一文档的高度相似片段跨入 tuning 和 acceptance，避免数据泄漏。Acceptance 结果生成后，不得根据结果改阈值或相关性标签。

## 4. 回归比较

同时报告绝对值和相对变化。例如 Recall@10 从 0.82 到 0.80 是绝对下降 0.02、相对下降约 2.44%。性能测试使用同一设备并交替运行基线和候选，减少温度、后台负载和缓存顺序偏差。微小差异若小于重复运行波动，应记为无明确结论。

## 5. 常用术语速查

| 术语 | 简义 |
|---|---|
| Gold label | 人工确认的期望结果 |
| Baseline | 用于比较的现有方案 |
| Ablation | 每次移除或改变一个因素以分析贡献 |
| Warmup | 不计入汇总的预热运行 |
| Tail latency | P90/P95/P99 等慢请求区间 |
| Throughput | 单位时间完成量 |
| Calibration | 置信度与实际正确率是否匹配 |
| Determinism | 相同输入是否产生相同结果 |
| Idempotency | 同一操作重复执行不会产生额外副作用 |
| Regression | 新版本相对基线退化 |
| Smoke test | 快速证明关键链路可启动，不等于完整验收 |
| Verification | 系统是否按设计实现 |
| Validation | 系统是否满足真实目标和用户场景 |

## 6. 当前可运行命令

```bash
npm run lint
npm test
npm run build
npm run m4:validate
npm run m4:smoke:embedding -- --allow-download --device cpu
npm run m4:benchmark -- --device cpu --batch-size 8 --split acceptance
npm run m4:build:obsidian-smoke
```

真实模型命令需要符合 M4 指南的 Node 版本、下载授权和设备条件。命令成功只证明对应层级通过；最终 GO 仍需协议批准、真实 Obsidian 设备验证和人工检查。
