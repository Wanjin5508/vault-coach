# LLM、聊天、流式输出与记忆测试参数

## 1. 延迟参数

- **TTFT**：发送请求到第一个可见 token 的时间；最直接影响“是否有响应”的感受。
- **生成速度**：输出 token 数 / 首 token 后生成秒数，单位 tokens/s。
- **端到端延迟**：用户提交到完整答案可用，包含 rewrite、retrieve、rerank 和生成。
- **阶段占比**：各 span 耗时 / 端到端耗时，用于定位瓶颈。
- **取消响应时间**：用户取消到网络、生成和 UI 都停止的时间。

流式 UI 已展示 first-token duration；若加入 OpenTelemetry，应为 rewrite、retrieve、rerank、prompt build、LLM request 和 persistence 建独立 span。

## 2. 质量参数

除 RAG 忠实度和引用指标外，还应测试：指令遵循率、目标语言正确率、结构化输出解析成功率、空响应率、截断率、重复生成率、有害或敏感内容泄露率。结构化输出需要同时统计首次成功率和重试后成功率，避免重试掩盖模型不稳定。

## 3. 上下文与记忆

当前默认 long-term memory 开启，`memoryTopK=4`、最多 150 条，单次会话最多保留 60 条消息。这些是配置参数。相关测试指标包括：

- 记忆检索 Recall@K 与 Precision@K。
- 过时记忆误用率和错误用户归因率。
- 上下文 token/字符预算、截断位置正确率。
- 无关记忆注入率和重复记忆率。
- 删除后残留率，应为 0。
- 关闭记忆后的网络、检索和注入调用次数，应为 0。

## 4. Provider 可靠性

Ollama 与 OpenAI-compatible 分别统计请求成功率、连接错误率、超时率、HTTP 状态分布、重试次数和重试放大比。云端场景还要检查 API key 不写入日志、Vault 内容只在明确功能需要和用户配置后发送。

## 5. 建议的首轮体验基线

在形成真实设备数据前，可以先观察 TTFT P50/P95、完整回答 P50/P95、流中断率、取消 P95、首次请求与暖请求差值。不要直接把通用互联网服务的延迟阈值套到本地小模型；应按本地 CPU、本地 GPU和云端分别建立基线。
