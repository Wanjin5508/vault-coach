# 前端交互与用户体验

## UI 结构

Vault Coach 的 UI 是 Obsidian 右侧栏中的 `ItemView`。顶部展示助手名、模式切换、知识库状态、文件数、chunk 数、向量状态和记忆数。问答模式显示聊天消息和输入框，考试模式显示创建考试、答题、评分结果和历史页面。

## 已优化的体验点

- 用户气泡靠右，并使用主题色区分；AI 气泡靠左。
- 回答生成期间有流式输出和忙碌状态。
- 中文输入法 composition 期间按 Enter 不发送消息。
- 来源区域支持 Markdown 渲染和内部链接跳转。
- Mermaid 代码块在来源摘录中避免触发无效图表错误。
- 考试结果页突出每题得分，字段标题加粗，来源路径可点击。

## 面试问答

### 1. 为什么用户问题和 AI 回答要视觉区分？

聊天界面中用户需要快速定位自己的问题。如果用户和 AI 都是白色气泡且垂直对齐，扫描成本很高。项目把用户气泡靠右并使用 Obsidian 主题色，AI 气泡靠左，符合常见聊天产品习惯。

### 2. 为什么输入法 composition 要特殊处理？

中文用户经常在中文输入法下输入英文或拼音，按 Enter 是确认候选词，不是发送消息。如果只监听 keydown Enter，会导致未编辑完就发送。项目通过 composition 状态判断，组词期间 Enter 不触发发送。

### 3. 为什么来源 Markdown 渲染会踩坑？

来源摘录来自用户笔记，可能包含 Markdown、代码块甚至 Mermaid。直接让 Obsidian 渲染不完整 Mermaid 代码块可能报 `UnknownDiagramError`。项目对来源渲染做保护，避免截断内容触发 Mermaid。

### 4. 为什么历史页来源链接需要手动绑定点击事件？

`MarkdownRenderer.render()` 能生成内部链接 DOM，但在插件自定义容器里并不总是自动处理跳转。项目在历史详情容器上做事件委托，点击 `.internal-link` 时读取 `data-href`，再调用 `openLinkText()`。

### 5. 考试模式为什么使用状态机 UI？

考试流程有明确阶段：创建、生成中、答题、评分中、反馈、历史。状态机可以避免多个 UI 状态混杂，也便于在异步任务中展示 loading 和错误处理。

### 6. 为什么设置页要重构模型配置？

早期“本地模型”和“云端模型”并列，用户可能同时填写两边，不知道实际使用哪个。后续改为在“模型”区域通过 provider 选择当前服务，只展示当前相关配置，降低认知负担。

### 7. 为什么要跟随系统语言？

当前主要用户是中文，但插件发布到社区后可能有英文用户。界面和设置随系统语言切换，可以降低维护多版本 README 或手动语言设置的成本。内置默认欢迎语也会随语言变化，自定义欢迎语不被覆盖。

### 8. 如何解释“前端性能优化”和“感知延迟优化”的区别？

性能优化是减少实际耗时，例如减少 embedding 计算；感知延迟优化是让用户更快看到反馈，例如忙碌状态和流式输出。当前项目优先做感知延迟优化，因为本地 LLM 性能取决于用户硬件。

### 9. 前端还有哪些可改进点？

可以增加索引进度条、embedding 批次进度、考试生成取消按钮、历史搜索、来源预览、模型健康检查，以及在移动端对长列表和大 Markdown 渲染做虚拟滚动或分页。
