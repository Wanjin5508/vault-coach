# 重构后软件架构

## 背景

本次重构前，项目虽然已经把知识库、RAG、模型调用、考试生成等能力拆到多个文件中，但 `src/main.ts` 仍然承担了过多职责：Obsidian 插件生命周期、命令注册、视图注册、索引状态机、对话状态、长期记忆、考试结果文件管理、考试历史 Markdown 序列化等逻辑都集中在一个入口文件里。

这会带来三个问题：

- 入口文件过大，后续新增功能容易继续堆到 `main.ts`。
- UI、设置页直接依赖主类实现，模块边界不清晰。
- 记忆管理、考试历史存储这类独立能力缺少明确所有权，难以单独测试和演进。

重构目标不是改业务行为，而是建立更清晰的模块边界，让未来扩展时优先新增或替换服务，而不是继续修改单个巨型文件。

## 总体结构

重构后的架构可以分成六层：

1. 插件入口层：保持 Obsidian 加载入口极薄。
2. 插件编排层：负责生命周期、服务初始化、索引状态机和对 UI 暴露 API。
3. UI 与设置层：只依赖稳定插件 API，不直接依赖主类实现细节。
4. 领域服务层：长期记忆、考试会话存储、考试 Markdown 格式化等按功能拆分。
5. 核心能力层：知识库、RAG、模型客户端、向量存储、考试引擎。
6. 工具层：错误识别、UI 格式化等通用辅助函数。

## 关键模块

### `src/main.ts`

现在只保留 Obsidian 插件默认导出：

```ts
import VaultCoach from "./vault-coach-plugin";

export default VaultCoach;
```

这样做的好处是入口文件不再承载业务逻辑。esbuild 仍然以 `src/main.ts` 作为入口，Obsidian 仍然加载打包后的 `main.js`，但真实编排逻辑已经移动到独立模块。

### `src/vault-coach-plugin.ts`

这是插件编排类，负责：

- 加载和保存设置。
- 初始化 `VaultKnowledgeBase`、`AdvancedRagEngine`、`ExamEngine`、`LongTermMemoryService`、`ExamSessionStore`。
- 注册视图、设置页、vault 文件事件。
- 管理知识库 dirty 状态、向量索引 dirty 状态、索引 busy 状态和取消控制器。
- 对 UI 暴露问答、考试、索引和历史相关 API。

它仍然是协调中心，但不再直接实现长期记忆算法，也不再直接格式化考试历史 Markdown。

### `src/plugin-api.ts`

定义 UI 和设置页可调用的稳定接口 `VaultCoachPluginApi`。

这个接口的价值是把“视图需要什么能力”从“主类具体怎么实现”里分离出来：

- `VaultCoachView` 依赖 `VaultCoachPluginApi`。
- `VaultCoachSettingTab` 依赖 `Plugin & VaultCoachPluginApi`。
- `VaultCoach` 主类显式 `implements VaultCoachPluginApi`。

这样以后如果主类拆成更多控制器，只要继续满足这个接口，UI 层就不需要同步改动。

### `src/plugin/command-registry.ts`

集中注册 Obsidian 命令和 ribbon 入口：

- `open-view`
- `reset-conversation`
- `rebuild-knowledge-index`
- `stop-knowledge-index`
- `clear-knowledge-index`

命令 ID 保持不变，用户可见行为不变。主类只调用 `registerVaultCoachCommands()` 和 `registerVaultCoachRibbon()`。

### `src/memory/memory-service.ts`

负责长期记忆的领域逻辑：

- 从已保存状态恢复记忆。
- 构造注入 prompt 的 memory context。
- 调用 RAG 引擎抽取长期记忆语句。
- 做本地去重、更新时间、访问时间和数量裁剪。
- 用中英文混合 tokenizer 做轻量相关性检索。

它不负责磁盘持久化。主插件在保存运行时状态时读取 `memoryService.getAll()`，在恢复状态时调用 `memoryService.hydrate()`。

### `src/exam/exam-session-store.ts`

负责考试结果的 vault 文件存储：

- 保存考试结果到 `.vault-coach/exams/`。
- 导出考试结果到用户指定目录。
- 列出考试历史。
- 读取和删除考试历史。
- 校验历史路径必须位于插件管理的考试目录中。
- 逐级创建导出目录，并处理导出路径冲突。

它不再直接拼 Markdown 内容，而是调用 `exam-session-markdown.ts`。

### `src/exam/exam-session-markdown.ts`

负责考试结果 Markdown 的纯文本规则：

- 将 `ExamSession` 格式化为可读 Markdown。
- 从历史 Markdown 中解析标题、创建时间、分数和最大分。
- 兼容旧历史文件中中文或英文的时间/分数字段。

这个拆分让“文件存储”和“Markdown 格式协议”分离。以后如果要支持 JSON 导出、PDF 导出或历史文件版本迁移，可以在这个边界上扩展。

### `src/ui/view-formatters.ts`

放置视图层的格式化函数：

- 聊天消息时间。
- 回答生成耗时。
- 考试历史时间。
- Notice 中展示的短错误消息。

这些逻辑原本是 `VaultCoachView` 的私有方法，抽出后 `view.ts` 更专注于 DOM 渲染和交互状态。

### `src/utils/errors.ts`

提供通用错误工具：

- `isAbortError()`：识别用户主动取消或 AbortController 触发的错误。
- `getErrorMessage()`：从 `unknown` 中安全提取错误文本。

主插件和视图层都复用这套逻辑，避免 AbortError 判断重复。

## 依赖方向

推荐依赖方向如下：

```text
main.ts
  -> vault-coach-plugin.ts
      -> plugin-api.ts
      -> plugin/command-registry.ts
      -> view.ts
      -> settings.ts
      -> memory/memory-service.ts
      -> exam/exam-session-store.ts
      -> knowledge-base.ts
      -> rag-engine.ts
      -> vector-store.ts

view.ts / settings.ts
  -> plugin-api.ts
  -> types.ts
  -> ui/view-formatters.ts
  -> utils/errors.ts

exam/exam-session-store.ts
  -> exam/exam-session-markdown.ts
  -> constants.ts
  -> types.ts
```

核心原则是：

- UI 层不能直接 import `vault-coach-plugin.ts` 或 `main.ts` 的具体类。
- 领域服务不直接操作视图，也不调用 Obsidian Notice。
- `main.ts` 不再承载业务逻辑。
- 新功能优先放入对应领域模块，再由插件编排层连接。

## 主要运行链路

### 插件加载

1. Obsidian 加载 `main.js`，入口来自 `src/main.ts`。
2. 默认导出的 `VaultCoach` 类来自 `vault-coach-plugin.ts`。
3. `onload()` 加载设置，初始化持久化存储、知识库、向量存储、RAG、考试引擎、记忆服务和考试存储服务。
4. 恢复运行时状态和知识库快照。
5. 注册右侧栏视图、命令、ribbon、设置页和 vault 文件事件。

### 问答流程

1. `VaultCoachView` 调用 `appendUserMessage()` 保存用户消息。
2. `VaultCoachView` 调用 `streamAssistantTurn()`。
3. 插件编排层确保知识库和向量索引可用。
4. `LongTermMemoryService` 构造 memory context。
5. `AdvancedRagEngine` 执行检索、rerank、prompt 构造和流式回答。
6. 插件编排层保存助手消息，调用记忆服务抽取长期记忆，并持久化运行时状态。
7. 视图层根据流式 token 和最终答案刷新 UI。

### 考试流程

1. `VaultCoachView` 通过插件 API 获取考试范围、文件选项和容量快照。
2. 插件编排层委托 `ExamEngine` 做范围分析和题目生成。
3. 用户提交答案后，插件编排层委托 `AdvancedRagEngine` 评分。
4. 保存或导出时，插件编排层委托 `ExamSessionStore` 写入 vault。
5. `ExamSessionStore` 调用 `formatExamSessionMarkdown()` 生成 Markdown。

### 自动索引同步

1. 插件通过 Obsidian vault 事件监听 create / modify / delete / rename。
2. 变更路径进入 pending set，并标记文本索引和向量索引 dirty。
3. 防抖或阈值触发增量同步。
4. `VaultKnowledgeBase` 同步变更文件。
5. `AdvancedRagEngine` 同步受影响 chunk 的向量。
6. 插件持久化知识库快照和运行时状态。

## 可扩展性收益

### 新增记忆策略

未来如果要改成向量记忆、按主题分组记忆或用户可编辑记忆，不需要改 UI。优先扩展 `LongTermMemoryService`，必要时再调整运行时状态结构。

### 新增考试导出格式

当前 Markdown 格式集中在 `exam-session-markdown.ts`。如果后续支持 JSON、CSV、PDF 或 DOCX，可以新增 formatter，而不是把逻辑塞回 `ExamSessionStore`。

### 新增命令

命令集中在 `plugin/command-registry.ts`。新增命令时，只需要确保命令调用的是 `VaultCoachPluginApi` 上的稳定能力，避免命令直接触达内部服务字段。

### 继续拆分 UI

`src/view.ts` 仍然是后续最大的拆分目标。推荐下一步按以下边界拆：

- `ui/qa-view.ts`：问答消息、输入框、来源展示。
- `ui/exam-setup-view.ts`：考试创建页、范围选择、文件管理。
- `ui/exam-taking-view.ts`：答题页。
- `ui/exam-review-view.ts`：评分结果页。
- `ui/exam-history-view.ts`：历史列表和历史 Markdown 展示。
- `ui/streaming-message.ts`：流式回答气泡和计时器。

拆分时应保留一个轻量的 `VaultCoachView` 作为状态容器和渲染入口，不要让子模块直接访问主插件类实现，继续通过 `VaultCoachPluginApi` 协作。

## 重构后的代码边界总结

- `main.ts`：打包入口。
- `vault-coach-plugin.ts`：插件生命周期和跨服务编排。
- `plugin-api.ts`：UI / 设置页与插件之间的协作契约。
- `plugin/command-registry.ts`：Obsidian 命令和 ribbon 注册。
- `memory/memory-service.ts`：长期记忆领域逻辑。
- `exam/exam-session-store.ts`：考试历史文件存储。
- `exam/exam-session-markdown.ts`：考试历史 Markdown 协议。
- `ui/view-formatters.ts`：视图格式化辅助。
- `utils/errors.ts`：通用错误工具。

## 验证方式

本次重构后已通过：

```bash
npm run build
npm run lint
```

这说明 TypeScript 类型检查、esbuild 打包和 ESLint 都能通过。由于本次改动主要是结构性迁移，核心行为通过保持原 API 方法名、命令 ID、持久化字段和 Markdown 格式规则不变来降低回归风险。
