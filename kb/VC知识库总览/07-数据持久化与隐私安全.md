# 数据持久化与隐私安全

## 持久化内容

项目有三类主要持久化数据：

- 运行时状态：聊天消息、长期记忆、最近自动索引时间，保存到 `runtime-state.json`。
- 知识库快照：chunk、文件 hash、embedding、索引统计，保存到 `index-snapshot.json`。
- 考试历史：保存到 vault 内 `.vault-coach/exams/*.md`。

## 隐私策略

Vault Coach 默认本地优先。使用默认 Ollama 时，请求发送到用户配置的本地服务。只有用户显式选择 OpenAI-compatible 服务并配置 API key 时，才会向远程服务发送问题、检索上下文、embedding chunk 或考试内容。

## 面试问答

### 1. 为什么要持久化索引快照？

构建索引和 embedding 成本较高，尤其是 vault 较大或本地模型较慢时。保存索引快照后，插件重启可以快速恢复 chunk 和向量，不必每次全量扫描和重新 embedding。

### 2. 如何判断索引是否需要重建？

知识库层保存 settings signature，主插件保存 embedding index signature。如果知识库范围、chunk size、overlap 或 embedding 模型配置变化，旧索引可能不再有效，需要标记 dirty 并重建。

### 3. 自动增量同步如何工作？

插件监听 vault 文件 create、modify、delete、rename 事件，把变更路径加入 pending set。通过防抖时间、最大等待时间和文件数量阈值决定何时同步。同步时只重算受影响文件的 chunk 和 embedding。

### 4. 为什么要保存文件 hash？

文件事件不一定代表内容真的变化。保存 content hash 后，增量同步可以跳过内容未变的文件，减少不必要的切块和 embedding 计算。

### 5. 长期记忆保存什么？

长期记忆保存从对话中抽取出的稳定事实，比如用户偏好、长期目标或项目背景。它不是保存所有上下文，而是提取未来可能有用的短语，并按相关性和时效性注入后续 prompt。

### 6. 云端模型会收到哪些数据？

如果用户启用云端回答模型，远程服务可能收到用户问题、检索到的 Markdown chunk、最近对话和相关长期记忆。如果启用云端 embedding，构建或刷新索引时会发送 Markdown chunk。考试模式还会发送选定上下文、用户答案和评分材料。

### 7. API key 如何保存更安全？

项目设置中保存的是 Obsidian SecretStorage 条目名称，而不是直接把原始 key 写进插件 data。这样可以降低配置文件泄漏时的风险。

### 8. 为什么隐藏考试目录要排除索引？

考试结果包含题目、参考答案和用户答案。如果被重新纳入知识库，后续考试或问答可能直接召回答案，造成数据污染。排除 `.vault-coach` 是为了保持原始知识库和插件生成数据的边界。

### 9. 这个项目还有哪些隐私改进空间？

可以在设置页增加更明确的远程调用确认、为云端 embedding 添加批量发送提示、为考试模式单独提示会发送用户答案、增加本地模型可用性检测，以及提供“一键清除运行状态和考试历史”的功能。
