# 考试模式设计与实现

## 设计目标

考试模式让用户基于当前知识库创建一次测试。它和问答模式不同：问答模式是临时对话，用户可以随时重置；考试模式是一份结构化测试，包含题目、用户答案、参考答案、评分、反馈和来源路径。

## 用户流程

1. 用户切换到考试模式。
2. 选择完整知识库或当前知识库范围内的某些目录。
3. 选择题目数量。
4. 插件基于选定 chunk 调用 LLM 生成题目。
5. 用户逐题作答。
6. 插件调用 LLM 评分。
7. 结果默认保存到 `.vault-coach/exams`。
8. 用户可以查看历史、删除历史或手动导出。

## 技术要点

- 前端状态机：`setup`、`generating`、`taking`、`evaluating`、`review`、`history`。
- 范围选择来自当前已索引 chunk，而不是重新扫描全 vault。
- 出题 prompt 使用 `<excerpt id="E1">` 结构，避免“上下文 n”泄漏到题目。
- 评分统一为百分制，每题 `maxScore = 100`，总分为平均百分制。
- 结果保存为 Markdown，带轻量 YAML metadata，历史页面可解析标题、时间、得分。
- 来源路径保存为 `[[path/to/file.md]]`，历史页面点击后跳转原笔记。

## 面试问答

### 1. 考试模式和问答模式在架构上如何隔离？

问答模式维护消息列表和输入框，考试模式维护独立的 `ExamSession` 和 UI phase。`VaultCoachView.render()` 根据 `activeInteractionMode` 分发到不同渲染逻辑，避免考试状态污染聊天消息。问答仍保持临时会话特性。

### 2. 为什么考试结果默认保存到隐藏目录？

考试结果是插件运行数据，默认写入 `.vault-coach/exams`，既能保留历史，又不打扰用户笔记目录。同时知识库扫描和自动索引会排除 `.vault-coach`，防止考试答案反过来污染后续检索。

### 3. 如何让用户仍能管理考试结果？

结果默认隐藏保存，但 UI 提供“考试历史”入口，用户可以查看过往记录、打开来源链接、删除记录。用户也可以手动导出到指定 vault 目录，生成一份可见 Markdown 副本。

### 4. 创建考试时如何选择目录？

知识库层从当前 chunk 的 `filePath` 推导父目录，生成 `ExamScopeOption`。用户可以选择完整知识库，也可以多选目录。目录选择尊重当前设置页知识库范围，不会越界到未索引区域。

### 5. 出题为什么只抽取部分 chunk？

一次把所有 chunk 发给模型会超出上下文并增加成本。项目用 `selectExamContextChunks()` 从范围内抽取代表性 chunk，并限制最大 chunk 数和字符数。当前策略偏轻量，适合插件内运行，但不保证覆盖全部知识点。

### 6. 如何控制题目生成的稳定性？

prompt 明确要求严格 JSON、字段 schema、不得引入上下文外事实、不得输出内部标签、评分标准必须 100 分制。温度设为 0.1，并在本地做字段清理、题目过滤、来源 fallback 和评分标准归一化。

### 7. 如何控制评分的一致性？

评分 prompt 要求每题 `max_score = 100`，总分是所有题目的平均百分制。代码层面 `normalizeExamEvaluation()` 会把单题 `maxScore` 强制设为 100，并用 `clampScore()` 限制分数范围。

### 8. 考试历史是如何解析的？

保存文件包含 YAML-like metadata，例如 `examId`、`createdAt`、`score`、`maxScore`、`scope`。历史列表读取 `.vault-coach/exams/*.md`，解析第一个 Markdown 标题和元数据，按创建时间或修改时间排序。

### 9. 考试模式遇到过哪些坑？

主要坑包括：模型输出非法 JSON、题目泄漏“上下文 n”、评分标准出现非百分制、历史来源链接不能跳转、默认保存到隐藏目录导致用户看不到结果、完整知识库选中时目录 checkbox 被禁用。项目分别通过 JSON 修复、prompt 改写、本地归一化、链接事件委托和 UI 逻辑调整解决。

### 10. 如果继续增强考试模式，你会怎么做？

可以增加题型选择、难度选择、限时、错题本、知识点覆盖统计、按目录生成题库、考试结果结构化索引，以及评分多维度拆分。更进一步可以引入面试官 Agent，根据用户回答动态追问。
