# 里程碑 5.8：知识域变更与派生数据生命周期开发规划

## 1. 背景与目标

Vault Coach 的索引、向量、确定性图谱、语义图谱和掌握度都保存在同一个 Vault 中。正常的文件增删改会通过 Vault 事件进入增量同步；但是用户可能在插件未运行时删除整个知识域，并在同一 Vault 导入一个完全不相关的新领域。此时旧的持久化快照若被直接恢复，会产生两个不可接受的结果：

1. 问答、学习图谱或 Dashboard 可能短暂显示旧领域事实；
2. 旧文本 chunk、向量、结构图和语义 shard 可能继续占用空间，直到用户知道应手动清理。

本里程碑提供**派生数据生命周期**，而不是把所有内容一并删除。最终用户体验为：

~~~text
打开插件
  → 快速核对当前 Vault 与上次已索引来源清单
  → 一致：安全恢复本地快照
  → 不一致：停止使用旧派生数据，明确提示“需要更新”
  → 重建索引：自动回收并重建文本 / 向量 / 结构图 / 掌握度快照
  → 需要语义图时：明确选择重建或重置语义治理记录
~~~

它是 VC-L6 自适应考试之前的基础设施修复。自适应考试依赖 Concept、Mastery 与 Assessment 的一致性；不能在“旧领域快照仍可能被读取”的前提下继续开发。

## 2. 当前事实与问题边界

### 2.1 现有保护

- 插件运行期间，Markdown/PDF 的 create、modify、delete、rename 会进入 debounce 后的增量同步；被删除文件的 chunk ID 会从文本索引和向量索引中移除。
- 向量存储保存为当前记录集的单一 Float32 shard 与 manifest，不按每次重建追加历史向量。
- 确定性图谱使用单一快照；语义图谱使用 manifest 管理的 shard，并在成功保存时删除不再引用的 shard。
- 【清除知识索引】会清除文本 snapshot、向量、确定性图与语义图。

### 2.2 当前缺口

1. 启动恢复只比较索引设置签名，不比较当前 Vault 的文件清单；插件关闭期间的大规模删除/导入可使旧 snapshot 被恢复。
2. 普通【重建知识索引】只重建文本、向量和确定性图；语义 Concept 图不会自动全量对齐新领域。
3. Mastery snapshot 会被标记 dirty，但不会删除；考试 Session、考试导出、聊天长期记忆也会保留。
4. 语义 Concept embedding 目前以 JSON number 数组保存，磁盘编码开销明显大于同样的 Float32 二进制向量。
5. 语义 shard 的常规写入会清理 manifest 已知的旧文件；但当前没有“递归扫描所有不被 manifest 引用文件”的垃圾回收器，异常中断或损坏 manifest 后的孤儿 shard 没有统一回收入口。

## 3. 数据分类与删除策略

| 分类 | 代表文件/对象 | 是否可再生 | 领域更换后默认处理 | 原因 |
| --- | --- | --- | --- | --- |
| 原始知识 | 用户 Markdown、PDF、附件 | 否 | 绝不由插件删除 | 用户拥有的事实源。 |
| 文本索引 | `index-snapshot.json`、内存倒排索引 | 是 | 自动失效；成功重建后覆盖 | 已索引文本的缓存。 |
| 向量索引 | `knowledge-index/vectors/*` | 是 | 自动清除并重建 | 向量只由当前 chunk 与 embedding 设置决定。 |
| 确定性结构图 | `.vault-coach/graph/graph-snapshot-v1.json` | 是 | 自动失效；成功重建后覆盖 | 文档、章节、链接、标签均来自当前 Vault。 |
| 掌握度 snapshot | `.vault-coach/mastery/*` | 是 | 自动删除/标记 missing | 它是当前 Concept catalog 与 Assessment 的派生读模型。 |
| 语义抽取与 embedding | `.vault-coach/graph/semantic/sections/*`、`embeddings/*` | 大部分可再生 | 不可读取；按变更范围 prune，必要时重建 | 模型抽取和 embedding 属于当前来源的派生结果。 |
| 语义治理记录 | merge、alias、确认/拒绝、手工关系 decision | 否 | 默认保留；大规模换域时让用户明确重置 | 这些是用户的人工判断，不能因普通离线修改静默删除。 |
| Assessment Session / 考试导出 | `.vault-coach/assessments/*`、`.vault-coach/exams/*` | 否 | 保留 | 用户学习历史与可导出文件。 |
| 聊天、长期记忆 | `runtime-state.json` | 否 | 保留并提供显式重置入口 | 可能仍被用户需要；不应静默抹除。 |

“自动清理”只针对可再生数据。特别是语义治理记录和 Assessment 是事实，不和缓存混在一个无提示的删除按钮中。

## 4. 目标架构

### 4.1 来源清单与一致性门

在 `KnowledgeBaseSnapshot` 中新增版本化 `sourceInventory`，不读取全文、不请求模型，只记录当前知识范围内 Markdown/PDF 的有序轻量描述：

~~~ts
interface SourceInventoryV1 {
  schemaVersion: 1;
  scopeSignature: string;
  files: Array<{
    path: string;
    size: number;
    modifiedAt: number;
  }>;
  fingerprint: string;
  generatedAt: number;
}
~~~

`fingerprint` 对排序后的 `path\0size\0modifiedAt` 序列稳定 hash。它的目标是低成本发现“当前 Vault 与快照不一致”，不是安全签名：增量同步和全量重建仍以内容 hash 为最终事实。

启动顺序改为：

~~~text
读取 snapshot
  → settings signature 匹配？
  → 读取当前 TFile 的 path / size / mtime 并生成 inventory
  → inventory 匹配？
       是：hydrate text/vector stats，允许加载图/语义/掌握度读模型
       否：不 hydrate 任一旧派生读模型，状态设为 source-sync-required
~~~

此门必须覆盖 Text Index、Vector Index、Knowledge Graph、Semantic Graph、Mastery 和 Learning Map；不能只阻止聊天检索而让 Dashboard 继续显示旧 Concept。

### 4.2 不一致后的两阶段恢复

**阶段 A：安全隔离。** 检测到不一致时，内存中的旧 index/graph/mastery 不得参与问答、考试范围、Learning Map 或 Dashboard。UI 显示“知识库在插件离线期间发生变化，需要重建”，但启动时不自动发起 embedding 或语义模型调用，避免把用户新导入的资料在未确认时发送给其配置的云端服务。

**阶段 B：用户发起重建。** 用户点击【重建知识索引】后：

1. 清空内存文本索引和向量 shard；
2. 扫描当前范围并构建全新 chunk；
3. 生成并保存当前向量；
4. 从当前 Vault 全量重建确定性图；
5. 删除 Mastery snapshot，状态变为 missing，保留 Assessment Session；
6. 对语义图执行不调用模型的来源对齐：删除已不存在 section 的 extraction、失效 Concept、失效候选、失效 semantic embedding；保留仍能绑定到当前 Concept 的用户 decision；
7. 成功写入新 `sourceInventory` 后才解除一致性门。

需要新概念抽取或用户选择“重置语义治理记录”时，才由独立的语义图谱重建操作调用模型。

### 4.3 大规模换域提示

比较旧/新 inventory 后，计算新增、删除、修改文件的占比；当变更比例达到 70%，或旧/新没有任何共同文件时，状态从普通 `source-sync-required` 升级为 `possible-domain-switch`。

此状态不自动删除用户确认的 merge/alias/手工关系，而是在重建完成后提供一次可解释操作：

> 检测到知识库主体已更换。文本、向量、结构图和掌握度已更新。是否同时移除旧领域的概念审核记录？考试历史与导出不会受影响。

操作必须展示将删除的 decision 数、受影响 Concept 数，并支持取消；取消时只保留仍能绑定到当前 Concept 的 decision，其余记录归入“失效治理记录”而不进入有效图。

### 4.4 持久化与 GC

1. 向量检索 chunk embedding 继续使用 Float32 二进制 shard；其空间预算为 `chunkCount × dimension × 4 bytes`，manifest 只保存元数据。
2. 语义 Concept embedding 从 JSON `number[]` 迁移到独立 Float32 binary shard + JSON manifest，schema version 升级后旧 JSON 一次性读取/转换或清理重建；不保留双份向量。
3. 语义 store 增加 `collectGarbage()`：列出 semantic 目录的可识别数据文件，删除不在当前 manifest 中且不属于可恢复 `.tmp/.bak` 的 shard。GC 在成功保存、显式清除和 schema migration 后执行；永不递归删除 `.vault-coach` 根目录。
4. 增加只读 `StorageFootprint` 诊断：按 text snapshot、vector、deterministic graph、semantic extraction/embedding、mastery、assessment/export 分类展示字节数、记录数和上次更新时间。

## 6. 关键算法与安全约束

### 6.1 Inventory diff

比较使用 `path` 作为主键：

- 仅新清单存在：`added`；
- 仅旧清单存在：`removed`；
- 两者存在但 size/mtime 改变：`modified`；
- 三者均为空且旧/新文件数为 0：`unchanged-empty`。

`changedRatio = (added + removed + modified) / max(oldCount, newCount, 1)`。当 ratio ≥ 0.70，或两侧均非空但共同路径为 0，视为疑似换域。重命名在离线启动时保守视作“删除 + 新增”；它只影响提示，不会删除原始笔记。

### 6.2 失败和取消

- inventory 不一致时，旧派生数据在磁盘上可暂留，但必须不可读；避免“为了清理”而在重建失败时同时失去恢复机会。
- rebuild 使用现有 abort 语义。取消后保持 `source-sync-required`，不得写入新的 inventory，也不得把半成品标记为 ready。
- 写入顺序为：新 text/vector/structure 成功 → semantic prune/mastery clear 成功 → snapshot 写入 inventory → 解除 gate。任一步失败都保持 gate。
- GC 只删除精确命名、可识别、且不在 manifest 中的数据 shard；不使用宽泛路径或未解析 glob，更不删除用户考试和原始文件。

### 6.3 隐私

启动 inventory 只读取本地文件路径、大小与 mtime。检测到变化不会自动调用 embedding、LLM 或云端服务；只有用户显式重建后，既有模型/隐私设置才生效。这个约束在本地 Ollama 与 OpenAI-compatible embedding/provider 下都必须一致。

## 7. 实现记录（2026-07-24）

### 7.1 已落地的来源一致性门

- 新增 `src/domain/index-lifecycle/source-inventory.ts`：对当前受范围配置约束的 `TFile` 按 `path / size / mtime` 排序并生成稳定 fingerprint；它不读取全文，也不触发模型调用。
- `KnowledgeBaseSnapshot` 写入 `sourceInventory`，版本升至 `3`。旧快照缺少该字段时按不可信快照处理，而不是“兼容性 hydrate”。
- `VaultCoachRuntime.initialize()` 先恢复聊天等非派生状态，再核对来源清单；不匹配时不加载 Text Index、Vector Stats、M2 图、语义图或 Mastery。
- 变更比例 `>= 70%`，或旧/新都非空但没有共同路径时，状态为 `possible-domain-switch`；其余不一致为 `source-sync-required`。

这样做的关键点是**安全隔离优先于磁盘立即删除**：若重建被取消或失败，旧文件可以暂留在磁盘，但没有任何用户可见读路径会使用它们。

### 7.2 重建、语义对齐与治理决策

- 用户主动重建后，文本、向量和确定性图按当前范围覆盖；随后 `SemanticGraphService.reconcileWithCurrentSources()` 只根据新的 Section + input hash 保留仍有效的 extraction。
- 对齐阶段会删除失效的 Concept、候选关系和 semantic embedding，不调用抽取或 embedding 模型；新 Section 仍需用户明确执行“重建语义概念图谱”。
- Mastery snapshot 在来源不一致的成功重建后显式清除；Assessment Session、考试报告、聊天和原始笔记不受影响。
- 新增命令 **重置语义图谱人工决策**。确认框会显示将清除的 decision 数和会影响的当前 Concept 数；它只清除确认/拒绝、别名、概念合并和手工关系，保留抽取结果与 embedding。

### 7.3 语义 embedding 存储与 GC

- `JsonSemanticGraphStore` 现将维度一致的 Concept embedding 保存为 Float32 二进制 shard，JSON 只保存 Concept 元数据、维度和 binary path。
- shard 名由 metadata **和向量实际值**共同内容寻址。新 shard 写入、metadata 写入、manifest 提交后，才回收旧 shard，避免中断时覆盖仍被旧 manifest 引用的数据。
- 旧 JSON `number[]` embedding 可以正常读取，并在下一次成功保存时惰性迁移为 binary shard。
- GC 只枚举 `.vault-coach/graph/semantic/` 内符合精确命名模式的 shard；不会宽泛删除 `.vault-coach`、考试记录或用户文件。

### 7.4 用户可见状态和存储诊断

- Ask/Exam 共享头部显示“知识库已变更”或“疑似知识域变更”；Learning Map 与 Learning Dashboard 显示相同原因，而不是将安全隔离误呈现为空数据。
- 新增命令 **查看 VaultCoach 派生数据存储用量**。它只读统计已知根目录中的文本快照、向量、确定性图、语义事实/向量、Mastery、Assessment 和隐藏考试报告；手动导出到任意用户目录的副本不会被扫描。
- 诊断同时显示文件数、字节数、可廉价获得的记录数及最近更新时间；不会删除或读取用户普通笔记。

### 7.5 回归与踩坑

已新增/扩展以下自动化覆盖：

- inventory 的稳定排序、单文件离线修改、范围变化、整库替换阈值；
- 缺少 `sourceInventory` 的旧 schema 快照安全降级；
- 离线修改后拒绝 hydrate，整库替换后重建为当前图；
- 当前来源对齐会 prune 语义事实，同时保留不再生效的用户 audit；
- 二进制 shard 内容寻址、旧 JSON 迁移、孤儿收集和 `clear()` 回收；
- Storage footprint 仅统计白名单数据根；
- 清除知识索引不删除 Assessment Session。

一个实际踩坑是：若 binary shard 指纹只包含 `inputHash`、时间和维度，理论上模型在相同输入下返回不同向量时仍可能重用旧路径。实现最终把 vector payload 的稳定 hash 纳入指纹，避免“新写入覆盖旧 manifest 正在引用的 shard”。
