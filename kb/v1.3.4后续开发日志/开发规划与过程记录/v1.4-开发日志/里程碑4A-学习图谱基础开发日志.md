# 里程碑 4A：学习图谱基础开发日志

## 1. 调整目的与后续顺序

原规划将“知识掌握度引擎”作为里程碑 4，并在其后实现 Dashboard 与图谱 UI。M3 完成后，项目已经具备可追溯的 Concept、关系候选、用户决策、有效图投影和关系方向，但尚未具备一个面向后续产品功能的稳定*图查询模型*。

掌握度的传播、薄弱点解释与学习路径都必须回答“当前有效 Concept 与关系是什么、方向为何、相邻节点如何取得”。因此，后续阶段调整为：

```text
M3 语义概念图谱（已完成）
        ↓
M4A 学习图谱基础（本阶段）
        ↓
M4B 知识掌握度引擎
        ↓
M5 最终 Learning Map / Progress Dashboard
        ↓
M6 自适应考试
        ↓
M7 复习推荐
```

这不是把最终可视化提前到掌握度之前，而是先交付一个可验证的图谱**领域读取模型与探索纵切**。M4A 不计算 Mastery，不做 Dashboard，不将 M3 的 `Concept review` 改造成 Learning Map。

建议从最新 `refactor` 新建 `feature/learning-graph-foundation`；M3 的 `feature/kg-mvp` 在 PR 合并后不继续承载下一阶段的功能提交。

## 2. 为什么不能直接开始 M4B

M4B 不能直接把 Assessment Event 绑定到 M3 的候选数据或某个 UI 的临时节点集合：

- 未确认 candidate 会随模型、embedding、Section 内容变化，不能参与高影响计算；
- Concept merge、alias 与 redirect 会改变“一个学习概念”的有效身份；
- `part_of`、`prerequisite_of`、`used_for` 有方向，而 `same_as`、`related_to`、`contrasts_with` 无方向；掌握度传播不能把它们混为一谈；
- M3 审核图的 36 节点上限是交互预算，不是数据查询契约；
- M5 也不能直接读取 `SemanticGraphStore` 或 Obsidian metadata cache，否则与 M3 审核图、M4B 算法各自形成不同的“有效图”定义。

所以 M4A 的产物是唯一的、可测试的 `LearningGraph` 查询边界。M4B 与 M5 均只通过该边界消费已确认概念图。

## 3. 基线、前置条件与不可破坏的边界

开始前必须确认：

- M1 的 `Assessment Session`、`Assessment Event` JSON 仍是考试与评分事实源；
- M2 的 `GraphSnapshotV1` 仍只保存确定性 Document / Section / Tag 结构事实；
- M3 的 `SemanticGraphService` 仍负责候选、用户决策、redirect 和 Effective semantic graph；
- Ask、Exam、Assessment、索引重建、M2 结构图和 M3 Concept review 已通过既有测试；
- M3 的模型设置保持显式 opt-in；M4A 不新增模型调用、embedding 调用或外部网络请求。

本阶段禁止：

- 将 pending candidate、被拒绝 candidate 或 ANN 相似度直接作为 Learning Graph 的有效边；
- 修改 `GraphSnapshotV1`、Assessment schema 或 Markdown 考试报告的兼容行为；
- 在插件 `onload` 扫描整个 Vault、预建全图布局或自动打开主工作区标签页；
- 将图形 renderer、Obsidian `Vault`、JSON Store 或 metadata cache 暴露给 domain service；
- 将“能渲染所有节点”作为完成标准；大 Vault 必须按查询预算和渐进展开工作。

## 5. 学习图查询契约

### 5.1 节点与边

默认视图只展示 **effective Concept** 节点。M2 Document / Section / Tag 节点是来源与结构层，只有在用户查看证据、当前文件上下文或主动展开来源时才加入投影。

建议领域契约：

```ts
interface LearningGraphNode {
  id: string;                         // Concept ID 或稳定结构节点 ID
  kind: "concept" | "document" | "section" | "tag";
  label: string;
  aliases: string[];
  sourcePaths: string[];
  evidenceCount: number;
}

interface LearningGraphEdge {
  id: string;
  type: SemanticRelationType | StructuralRelationType;
  sourceNodeId: string;
  targetNodeId: string;
  directed: boolean;
  origin: "semantic" | "structural" | "user";
  evidence: GraphEvidenceRef[];
}

interface LearningGraphQuery {
  focusNodeId?: string;
  search?: string;
  filePath?: string;
  folderPath?: string;
  relationTypes?: SemanticRelationType[];
  includeStructuralContext?: boolean;
  depth?: 0 | 1 | 2;
  maxNodes?: number;                  // hard cap: 150
  maxEdges?: number;                  // hard cap: 300
}
```

具体字段可随实现细化，但以下不变式必须固定：

1. 相同 M2/M3 状态与相同 query 得到相同节点、边、排序和 `truncated` 标记；
2. 所有 semantic edge 都来自 M3 effective graph，且保持 M3 的 Concept redirect 结果；
3. 有向关系保持 `source → target`；无向关系规范化端点并显式 `directed: false`；
4. 每个节点和边都能回到 Concept evidence 或 M2 source location；
5. 预算不足时返回完整、可解释的局部投影，而不是隐式截断为任意列表。

### 5.2 关系方向与 M4B 传播边界

| 类型 | 图中方向 | M4A 含义 | M4B 默认处理 |
|---|---|---|---|
| `same_as` | 无向 | 等价候选已由用户确认，但仍保留来源 | 不做自动双向传播；merge/alias 另行解析 |
| `related_to` | 无向 | 关联探索 | 默认不传播 Mastery |
| `contrasts_with` | 无向 | 对比探索 | 默认不传播 Mastery |
| `part_of` | 有向 | 组成关系 | 仅作为未来可配置的聚合依据 |
| `prerequisite_of` | 有向 | 学习先决关系 | 未来可用于路径与弱项解释，不默认反向推导掌握 |
| `used_for` | 有向 | 用途关系 | 默认只用于探索与解释 |

M4A 不定义具体分数传播公式，但必须保证 M4B 能无歧义读取方向、类型、证据和来源。

### 5.3 容量评估与本地保护（M4A 步骤 0）

在建立任何新的学习图投影前，先交付纯函数 `GraphCapacityAssessment`。它是**语义图本地计算的准入与降级策略**，不是对整个 Vault、M2 确定性结构图、文本索引、Ask 或 Exam 的禁用开关。

M3 虽然已经通过 LSH 候选索引避免了概念两两 embedding 比较，但仍包含 Section 抽取、概念 embedding、候选维护、持久化和审核图更新。若在很大的 Vault 上默认自动执行，这些工作会挤占 Obsidian 的前台资源；M4A/M4B 又会在其有效图上继续查询和计算，因此保护必须早于新的图功能。

评估输入只取本地、已知的计数：M1/M2 的 `fileCount`、`chunkCount`、Document/Section/edge 数，M3 的 extraction、Concept、candidate、confirmed relation、embedding 数，以及已有向量索引 `vectorCount × dimension × 4` 的原始字节估算。维度未知时标记为 `unknown`，绝不把未知误判为安全。

所有阈值采用“任一指标触发”的保守策略，而非只按文件数判断。首次实现使用以下可解释的初始预算，并在真实 Vault 基准数据后再校准：

| 级别 | 触发条件（任一） | 行为 |
|---|---|---|
| `local` | 未超过警告线 | 允许用户手动语义重建；自动同步按原设置工作。 |
| `warning` | `chunkCount > 8,000`、Section `> 1,000`、可抽取文本估算 `> 10 MB`、Concept `> 2,000`、候选/有效关系合计 `> 10,000` | 仍允许显式手动重建；停止自动语义同步，并在 UI 返回明确警告。 |
| `service-preferred` | `chunkCount > 25,000`、Section `> 2,500`、文本 `> 25 MB`、Concept `> 5,000`、候选/有效关系 `> 25,000`、原始 embedding `> 128 MB` | 阻止本地 M3 语义重建；保留既有已落盘图的只读查询，提示未来独立服务入口。 |
| `service-required` | `chunkCount > 50,000`、Section `> 5,000`、文本 `> 50 MB`、Concept `> 10,000`、候选/有效关系 `> 100,000`、原始 embedding `> 256 MB` | 同上，使用更强的“建议独立服务”说明；本阶段不连接网络服务。 |

保护策略仅影响**后续本地语义构建和自动同步**：现有有效图、Learning Map 局部查询和所有非语义功能继续可用。`service-preferred`/`service-required` 现在只提供可测试的决策和提示，不发送 Vault 内容、不新增服务设置，也不伪造外部服务已部署。

### 5.4 大型 Vault 查询预算

M4A 的“完整”含义是查询能力完整，不是一次渲染全量数据。

- 默认最多 150 节点、300 边；
- 搜索、当前文件/目录、Focus node 与关系类型是缩小范围的第一层手段；
- 超预算时按确定性优先级保留：focus、直接邻居、已确认 semantic edge、结构来源上下文、其余匹配项；
- 返回 `truncated`、`hiddenNodeCount`、`hiddenEdgeCount` 或等价元数据；
- renderer 只接收 `LearningGraphProjection`，不拥有全 Vault snapshot；
- 复杂布局、聚类和动画都可取消，并在 View 关闭时释放。

## 7. M4B 与 M5 的明确交接

### M4B：知识掌握度引擎

M4B 在 M4A Definition of Done 后开始。它只读取：

```text
Assessment Event
      +
LearningGraphProjection / 有效 Concept 查询
      ↓
ConceptMasteryState（可重算、可追溯、算法版本化）
```

M4B 实现分数、难度、置信度、时间衰减、趋势、错误聚合、下一次复习时间与增量重算，但不把未确认关系或纯相似度候选用于掌握度传播。

### M5：最终 Learning Map / Progress Dashboard

M5 在 M4B 状态稳定后实现：

- 掌握度、置信度、遗忘风险、覆盖率和薄弱点着色；
- Dashboard、待复习与学习路径；
- 更成熟的图谱 renderer、聚类、渐进展开与布局状态保存；
- 从弱项或图谱节点发起定向考试；
- 掌握度解释界面。

M5 的视觉和交互将消费 M4A 的 projection 与 M4B 的 Mastery read model，而不是绕过它们重新计算图谱含义。
