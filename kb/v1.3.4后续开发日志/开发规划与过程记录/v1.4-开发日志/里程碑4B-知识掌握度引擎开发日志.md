# 里程碑 4B：知识掌握度引擎开发日志

## 1. 目标、范围与完成边界

M4B 将 M1 的不可变 `AssessmentEvent` 和 M4A 的 effective Concept catalog 转换为可重算、可追溯的 `ConceptMasteryState`。它交付领域计算、派生快照、增量更新和 Application API；不在本阶段实现 Dashboard、图谱着色、学习路径、复习任务 UI 或自适应出题，它们属于 M5–M7。

```text
Assessment Session JSON（M1，事实源）
        +
LearningGraph concept catalog（M4A，只含 effective Concept）
        ↓
MasteryEngine（纯函数，无模型调用）
        ↓
Mastery snapshot（派生缓存，可全量重建）
        ↓
M5 Learning Map / Dashboard
```

本阶段绝不读取 Markdown 考试报告、pending/rejected candidate、ANN 相似结果或 renderer 临时选择状态。掌握度不是考试总分的别名；它只能表示某个已解析 effective Concept 的可追溯证据聚合。

## 2. 当前基线与关键事实

- M1 的 Assessment Session JSON 是唯一考试事实源；事件是 append-only，重新评分由 `supersedesEventId` 替代旧事件；
- M3 提供了可合并、可 redirect 的 effective Concept；M4A 已将其封装在 `LearningGraphQueryService` 中；
- M4A 的 `LearningGraphProjection` 为 renderer 设有 150 节点预算，**不能**被 M4B 当作全量 Concept 列表；
- 当前旧考试的 `AssessmentEvent.conceptIds` 多为 `exam-topic:*` provisional ID，而不是 M3 的 `concept:*` ID。因此，不能把 ID 字符串不加验证地写入掌握度状态。

最后一点决定本阶段必须有显式绑定解析层：直接命中 effective Concept ID 才可绑定；若为旧 provisional ID，仅可用 Assessment Session 中保存的 topic label 与 Concept display name/Alias 做**唯一的规范化精确匹配**。匹配到零个或多个 Concept 时均保留为未绑定证据，不能用 embedding、模糊匹配或候选关系猜测归属。

## 3. 数据契约

新增 `src/domain/mastery/mastery-types.ts`，主要契约如下：

```ts
type MasteryLevel = "unknown" | "weak" | "developing" | "proficient" | "mastered";
type MasteryTrend = "unknown" | "improving" | "stable" | "declining";

interface ConceptMasteryState {
  conceptId: string;
  masteryScore: number | null;
  confidence: number;
  level: MasteryLevel;
  assessmentCount: number;
  effectiveEvidenceCount: number;
  lastAssessedAt: number | null;
  lastReviewedAt: null; // M5/M7 的人工复习事实尚未存在
  nextReviewAt: number | null;
  commonErrorCodes: AssessmentErrorCode[];
  trend: MasteryTrend;
  evidence: MasteryEvidenceContribution[];
  calculatedAt: number;
  algorithmVersion: string;
}
```

`MasteryEvidenceContribution` 至少保存 event ID、绑定方式、原始分数、有效权重、时间和错误类型；因此任意状态可回溯至具体 Assessment Event。没有有效证据的 Concept 必须返回 `masteryScore: null`、`confidence: 0`、`level: "unknown"`，绝不以 `0` 冒充“不会”。

派生快照写入 `.vault-coach/mastery/mastery-snapshot-v1.json`，其中保存 schema version、算法版本、计算时间、所有状态和未绑定事件 ID。该文件不是事实源；删除或算法升级后可由 Assessment Session JSON 和 effective Concept catalog 重建。

## 4. v1 算法与可解释性

对 Concept `c` 的每条已绑定、未被 supersede 的事件 `i`：

```text
score_i = normalizedScore
weight_i = difficultyWeight × evidenceConfidence × evaluationConfidence × exp(-λ × elapsedDays)
mastery(c) = Σ(score_i × weight_i) / Σ(weight_i)
confidence(c) = 1 - exp(-Σ(weight_i))
```

固定且版本化的 v1 参数：

| 参数 | 值 |
|---|---:|
| `basic` 难度权重 | 0.8 |
| `intermediate` 难度权重 | 1.0 |
| `advanced` 难度权重 | 1.2 |
| `λ`（每天衰减） | 0.03 |
| `mastered` 最低分数 | 0.85 |
| `mastered` 最低置信度 | 0.60 |

等级阈值为 weak `<0.45`、developing `<0.70`、proficient `<0.85`、mastered `>=0.85` 且置信度足够；高分但证据不足时最多为 proficient。趋势比较时间排序后较新的半数与较早的半数的加权成绩，差异大于等于 0.10 才标记 improving/declining，否则 stable；少于两条有效证据为 unknown。复习时间是纯建议：weak +1 天、developing +3 天、proficient +7 天、mastered +21 天；它不创建任务，也不伪造“已复习”事实。

算法以 `mastery/v1` 标识。修改任何权重、阈值、衰减或趋势规则时必须递增版本；快照版本不匹配时只允许全量重算。

## 5. 架构与增量策略

```text
src/
├── domain/mastery/
│   ├── mastery-types.ts
│   ├── mastery-engine.ts
│   ├── mastery-binding-resolver.ts
│   └── mastery-integrity.ts
├── app/mastery/
│   └── mastery-service.ts
└── infrastructure/storage/
    └── json-mastery-store.ts
```

M4A 新增 `getConceptCatalog()` 读取 API：它只返回全部 effective Concept 的 ID、显示名、Alias 和来源路径，不返回 renderer projection，不读取 pending candidate，也不暴露 `SemanticGraphStore`。M4B 只能通过该 API 获得可学习概念。

全量重算读取全部 Assessment Session JSON、消除 superseded event、解析绑定后一次计算所有 catalog Concept。保存一场考试后，服务只取该 Session 的绑定候选 Concept，并用全事件集合对这些 Concept 调用 `recalculateConcepts()`；这是“重新计算受影响 Concept”，不是全图重算。概念合并、Alias 或 effective graph 变化会标记派生快照 dirty，不自动进行昂贵全量重算。

服务在 M4A `service-preferred`/`service-required` 容量状态下不启动新的本地 Mastery 计算，但继续提供上次成功快照的只读访问；M1/M2、Ask、Exam 和已有数据永不因此失效。

## 6. 实现步骤

本里程碑按以下顺序一次性实施，完成后统一验证。

### 步骤 1：冻结样本、绑定规则与算法边界

- 新增事件样本：直接 Concept ID、唯一 alias、歧义 alias、未绑定 provisional topic、重新评分 supersede、不同难度和不同时间；
- 为 v1 权重、衰减、unknown、等级、趋势、错误聚合和复习时间建立纯函数测试；
- 断言 pending/rejected candidate 不可通过 catalog 进入引擎。

### 步骤 2：实现 Mastery 领域模型与纯引擎

- 新增领域类型、绑定解析器、完整性校验、`MasteryEngine`；
- 以纯输入输出实现全量和单 Concept 重算；
- 保证稳定排序、事件去重、supercede 处理和算法版本校验。

### 步骤 3：实现派生快照存储与 MasteryService

- 新增本地 JSON Store；严格验证 schema，损坏或旧算法快照不污染 Assessment 事实；
- 服务负责 load、全量 rebuild、单 Session 增量 sync、dirty/错误/容量状态和只读 snapshot；
- 不在 `onload` 扫描或重算，启动时仅加载派生快照。

### 步骤 4：扩展 M4A Catalog 与 Application Facade

- 为 Learning Graph 增加全量 effective Concept catalog 查询；
- 在 Application Container 装配 MasteryService；
- 添加 `application.mastery` 只读状态/查询与显式 rebuild API；
- 新考试事实和 Markdown 投影成功后尝试增量更新；失败只记录 Mastery 状态，不能让考试保存失败；
- M3 effective graph 变化时只标记 mastery dirty。

### 步骤 5：命令、文档与回归

- 注册稳定命令 **Rebuild concept mastery**；不在 M4B 向 Learning Map 添加 Dashboard；
- 记录本地存储、算法版本、绑定限制与容量降级；
- 运行 build、lint、测试与 Obsidian 手动流程，确认 Ask/Exam/M3/M4A 行为不回归。

## 7. Definition of Done

- [x] Assessment Event 可经直接 ID 或唯一精确 label/Alias 绑定到 effective Concept；歧义和未知绑定保持未绑定；
- [x] 全量/增量计算是确定性的，并正确排除 superseded event；
- [x] 分数、难度、证据置信度、评分置信度、时间衰减、等级、趋势、错误聚合和复习时间均可追溯；
- [x] 无有效证据的 effective Concept 是 `unknown`，不是零分；
- [x] 快照含算法版本且可删除重建；版本变更要求全量重算；
- [x] 新考试只重算受影响 Concept，图谱变更只标记 dirty；
- [x] M4B 只消费 M1 JSON 与 M4A catalog，不消费 Markdown、候选关系、embedding 或 renderer 状态；
- [x] 大 Vault 容量降级不影响已有快照读取、Ask、Exam 或 Assessment 保存；
- [x] `npm run build`、`npm run lint`、`npm test`、`git diff --check` 通过。
