# 里程碑 0：第二轮架构重构开发文档

## 1. 文档目的

本文档把《v1.3.4 后续规划》中“里程碑 0：第二轮架构重构”转换成可直接执行的编程步骤。

本里程碑只调整结构和依赖方向，不增加用户功能，不改变现有问答、PDF、考试、历史、设置和索引行为。完成后，项目应形成可继续承载知识图谱、Assessment、Mastery、Progress 和推荐功能的模块化单体架构。

## 5. 强制依赖规则

目标依赖方向：

```text
presentation ───────→ app ───────→ domain
      │                │             ↑
      │                └──── ports ──┤
      └── Obsidian UI                 │
                                     │ implements
infrastructure ───────────────────────┘

vault-coach-plugin.ts → application-container.ts
main.ts               → vault-coach-plugin.ts
```

必须遵守：

- `domain/**` 不得导入 `obsidian`、`presentation/**`、`vault-coach-plugin.ts` 或具体存储实现；
- `app/**` 不得创建 DOM、调用 `Notice` 或读取 `WorkspaceLeaf`；
- `presentation/**` 只能调用 Application API，不得访问 `VaultKnowledgeBase`、`VectorStore`、`AdvancedRagEngine`、`ExamEngine`；
- `infrastructure/**` 可以依赖 domain 中的接口和类型，但 domain 不得反向依赖 infrastructure；
- `vault-coach-plugin.ts` 只做对象组装、注册和事件转发，不实现问答、考试、索引算法；
- 新代码不得再从 `src/types.ts` 导入；该文件只用于迁移期间兼容旧 import；
- 考试域不能依赖 RAG 具体类；评分只依赖最小模型端口；
- 文档知识库不能出现方法名或类型名中的 `Exam`。

在 `eslint.config.mts` 增加按目录的 `no-restricted-imports` override，至少覆盖上述规则。规则必须基于目录 pattern，而不是逐文件黑名单，确保后续新文件也受约束。

## 6. 核心契约设计

### 6.1 通用文档索引端口

在 `src/domain/documents/document-index-reader.ts` 新建：

```ts
export interface DocumentIndexReader {
    isReady(): boolean;
    getStats(): KnowledgeBaseStats;
    getAllChunks(): IndexedChunk[];
    getChunkById(chunkId: string): IndexedChunk | null;
    getChunksByIds(chunkIds: readonly string[]): IndexedChunk[];
    getChunksByFilePath(filePath: string): IndexedChunk[];
    getFileRecords(): KnowledgeBaseFileRecord[];
    getFileRecord(filePath: string): KnowledgeBaseFileRecord | null;
    readDocumentText(filePath: string): Promise<string | null>;
}
```

注意：接口名称必须是通用文档语言，不能使用 `Exam`。`VaultKnowledgeBase` 实现该接口；Exam、RAG 和后续 Graph 都只依赖此端口。

同一文件再定义只供应用层索引协调器使用的维护端口：

```ts
export interface DocumentIndexMaintenance {
    clear(): void;
    rebuild(signal?: AbortSignal): Promise<KnowledgeBaseSyncResult>;
    syncChangedFiles(paths: readonly string[], signal?: AbortSignal): Promise<KnowledgeBaseSyncResult>;
    getSettingsSignature(): string;
    importSnapshot(snapshot: DocumentIndexSnapshot): void;
    exportSnapshot(): DocumentIndexSnapshot;
}
```

考试、RAG 和 Graph 只能接收 `DocumentIndexReader`；只有 `KnowledgeIndexCoordinator` 接收 `DocumentIndexMaintenance`。`DocumentIndexSnapshot` 是与 Obsidian 无关的纯数据结构，具体存储路径和 JSON 读写仍属于 infrastructure storage。

### 6.2 考试评分模型端口

在 `src/domain/model/model-gateway.ts` 定义由 domain 拥有、由 infrastructure 实现的最小模型端口：

```ts
export interface JsonGenerationGateway {
    generateJsonAnswer(
        messages: LocalChatMessage[],
        temperature: number,
        signal?: AbortSignal,
    ): Promise<string>;
}
```

`LocalModelClient` 实现该接口。`ExamEvaluationService` 的构造函数只接收 `JsonGenerationGateway`，不得 import `LocalModelClient`。

### 6.4 应用事件

在 `src/app/application-events.ts` 定义类型安全的最小事件总线：

```ts
export type ApplicationEvent =
    | { type: "state-changed" }
    | { type: "index-state-changed" }
    | { type: "conversation-changed" }
    | { type: "exam-history-changed" };
```

`VaultCoachApplication.subscribe(listener)` 返回取消订阅函数。插件层在订阅回调中调用 `refreshAllViews()`。这样应用层不需要认识 `WorkspaceLeaf` 或 `VaultCoachView`。

### 6.5 旧 API 兼容适配器

保留现有扁平 `VaultCoachPluginApi` 的方法名和签名，并在 `src/presentation/legacy-plugin-api-adapter.ts` 实现：

```text
旧 getMessages()                    → application.chat.getMessages()
旧 streamAssistantTurn()           → application.chat.streamAssistantTurn()
旧 getExamScopeOptions()           → application.exam.getScopeOptions()
旧 createExamSession()             → application.exam.createSession()
旧 evaluateExamSession()           → application.exam.submitSession()
旧 rebuildKnowledgeBase(showNotice)→ application.index.rebuild()
旧 refreshAllViews()               → 由 adapter 注入的 presentation callback
```

需要显示 `Notice` 的旧方法由 adapter 捕获结果并调用 Notification Port；Application 本身不接收 `showNotice`。兼容 adapter 在里程碑 0 保留，等所有 UI 使用分组 API 后再单独删除，不能在本轮一边拆 UI 一边强制全量改 API。

- 评分所需的 JSON 解析/修复逻辑。

JSON 解析/修复如果也被考试生成服务需要，应提取为 domain 可复用的 `StructuredOutputService`，通过 `JsonGenerationGateway` 工作；不要让 `ExamEvaluationService` 反向依赖 RAG 的私有 helper。

当前 `AdvancedRagEngine.generateExamSession()` 没有任何调用点，并与新版 `ExamEngine` 重复。它连同 `GeneratedExamPayload`、旧蓝图/旧题目归一化辅助函数一并删除，而不是迁移到评分服务。删除前用 `rg` 再确认唯一引用。

`ExamEvaluationService` 公开方法：

```ts
evaluate(session: ExamSession, userAnswers: readonly string[]): Promise<ExamEvaluation>
```

应用层的 `submitSession()` 负责把 `userAnswers`、`evaluation` 和 `status: "submitted"` 合并回 `ExamSession`。评分服务只计算评分，不保存文件、不改变 session、不显示 Notice。

#### 保持不变的评分行为

- 每题 100 分；
- 总分 100 分；
- 缺失题目评分时按 0 分和默认反馈补齐；
- 分数 clamp 到 0～100；
- 总分 fallback 为各题百分制平均分；
- 原 `overallFeedback`、`feedback`、`improvement` 默认文案不变；
- temperature 和 Prompt 文本不在本里程碑优化。

## 12. 风险与控制措施

| 风险 | 控制措施 |
|---|---|
| 纯移动导致 import 大面积破损 | 每次只移动一个模块族；保留显式 compatibility barrel；每步 build |
| UI 拆分后状态丢失或重复渲染 | Controller 成为唯一状态所有者；View 只渲染 state；补状态转换测试 |
| Abort/timer 在卸载后泄漏 | Controller、Coordinator、Application 都实现 dispose；onClose/onunload 测试 |
| 考试评分结果细微变化 | 原 Prompt 和归一化代码原样迁移；用固定模型响应做 golden 测试 |
| 旧考试历史无法读取 | 改动前固定中英文旧格式 fixture；本轮不改 Markdown schema |
| Application 变成新的 God Class | Application 只聚合分组 API；状态分别属于 ChatService、IndexCoordinator、Exam 服务 |
| Domain 仍依赖 Obsidian | ESLint override + import boundary test 双重阻止 |
| legacy adapter 永久存在 | 标注 deprecated；Controller 迁移到分组 API；后续单独清理，不阻塞 M0 |
| 文件移动与算法优化混在一起 | M0 禁止 Prompt、评分、检索参数和持久化 schema 优化 |
