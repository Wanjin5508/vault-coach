# 里程碑 7：复习建议与学习计划开发记录

> 实施状态（2026-07-25）：VC-L7 的本地推荐、行动事实、Dashboard 操作和 Markdown 导出已实现，并通过自动化回归；仍需要在真实 Obsidian Vault 手工验证来源跳转、剪贴板权限和按来源范围进入考试的体验。

## 1. 要解决的问题

M4B 已经能从结构化考试事实得到可重建的掌握度，M5 的学习仪表盘也能展示它们。但用户仍需要自己把“薄弱”“未覆盖”“复习到期”和“前置知识不足”翻译为下一步行动。M7 把这些**已存在且可追溯的本地事实**收敛为最多五项建议，而不把它伪装成一个不可解释的总分或待办软件。

建议系统的边界如下：

1. 它只消费 effective Concept、已确认 `prerequisite_of` 关系、准确来源 chunk 和 Mastery/Assessment 派生事实；pending/rejected candidate、显示用自动关系、相似度和模型评分器类型不参与排序。
2. Recommendation 是可丢弃、可重建的派生读模型；用户点击操作只写 ReviewActionEvent，不修改 Concept、图谱、Assessment 分数或 Mastery。
3. `suggestedExamMode` 只是行动提示：练习型建议默认显示 simple，专题练习可显示 challenge。它不参与 priority，且不会预先锁定考试模式；进入考试设置后用户仍可改，分析后仍受 M6 的“返回设置才能改模式”规则约束。
4. Lite 不接入日历、提醒服务、网络或后台任务。导出是用户主动复制 Markdown；未来日历接缝只有接口，没有实现。

## 2. 实际架构与数据流

~~~text
effective LearningGraph + confirmed prerequisite relations
Mastery snapshot + saved Assessment facts
                 ↓
RecommendationService（可缓存的应用读模型）
                 ↓
domain/recommendation pure planner ───── ReviewActionEvent JSON
                 ↓                            ↑
ProgressSnapshot（最多 5 个 open 项）        用户：完成 / 7 天后 / 忽略 / 恢复
                 ↓
Learning dashboard：解释、来源、范围考试、Markdown
~~~

依赖方向严格保持为 `Presentation → Application → Domain`。`src/domain/recommendation/` 不导入 Obsidian、DOM、JSON adapter、模型客户端或网络 API；它只接收标准化概念、Mastery 和事件。`JsonReviewActionStore` 只是基础设施端口实现，Dashboard 只能通过 `RecommendationApplicationApi` 写操作。

## 3. 已实现内容

| 目标 | 实现 | 关键约束 |
|---|---|---|
| 确定性推荐领域 | `recommendation-types.ts`、`recommendation-policy.ts`、`recommendation-planner.ts` | policy 版本为 `recommendation/v1`；按弱项、到期、未覆盖、低置信、近期覆盖惩罚、已确认前置关系和有界局部连接度排序，最后以稳定 id 打破平局 |
| 可证明来源 | planner 先过滤 `sourceChunkIds` 为空的 Concept | 不从概念名称、embedding 相似度或 renderer 节点猜测来源 |
| 可恢复的用户事实 | `.vault-coach/recommendations/review-actions-v1.json` | schema `1`、append-only event、损坏/格式不合法时拒绝覆盖；建议本身不写盘 |
| 延后规则 | `deferred` 附带日期时到期自动回到 `open`；无日期则保留为延后，直到用户恢复 | 这避免把“稍后”误当成“已完成” |
| 推荐服务 | `RecommendationService` 读取 LearningGraph/Mastery，形成 queue 和不超过 5 项 primary | 图、语义治理、Mastery 和保存的新 Assessment 事实发生变化时统一失效重算 |
| 应用/API | `RecommendationApplicationApi`、`ProgressService` 投影 | 支持读取、提交操作、导出 Markdown；不向 UI 泄漏 JSON adapter |
| Dashboard | 建议原因、建议模式提示、查看来源、按来源范围考试、完成/延后/忽略/恢复、复制 Markdown | 来源路径每次由当前 effective catalog 解析；无路径明确提示，不猜测跳转 |
| 未来日历接缝 | `RecommendationReminderCalendarAdapter` | 仅声明显式 opt-in adapter；没有第三方调用、token、后台同步或网络请求 |

### 3.1 排序规则与解释性

每项 Concept 建议将以下 reason codes 显示给用户：`weak-mastery`、`developing-mastery`、`review-due`、`unassessed`、`low-confidence`、`recently-covered`。薄弱/发展中/到期产生复习建议，未评估产生探索建议，纯低置信产生专题练习建议。对“弱目标的有效已确认前置知识”额外生成 `review-prerequisite`。

权重属于版本化 policy，而不是隐藏模型结论：弱项 500、到期 420、发展中 340、确认前置 300、未评估 260、低置信 200、每条有效前置关系的局部连接度加分 25（最多 100）、7 天内最近评估惩罚 80。优先级不读取 `simple`/`challenge`、模型提供商或 evaluator 类型。相同输入、当前时间和 action log 必须得到相同顺序。

局部“重要性”只统计当前 effective graph 中已确认 `prerequisite_of` 的端点数量，使用 `high-connectivity` reason code 并在 policy 中封顶。它不读取图渲染器的节点大小、位置、Canvas 布局或 embedding 相似度；这些都不是学习事实。若将来需要更复杂的重要性指标，仍必须在 Domain 中定义有界、版本化、可解释的有效关系度量，并补充回归测试。

### 3.2 考试与评分隔离

“以此范围考试”只把推荐 Concept 的**当前来源文件路径**送进既有范围考试设置。它不直接生成题目、不替用户选择题型，也不绕过 M6 分析。Dashboard 可能写出 `suggestedExamMode`，但用户仍在设置页选择 simple/challenge；评分和 Assessment 事件继续由原路径生成。因此完成、忽略或恢复建议不能污染图谱和分数，真正完成考试后才通过 Assessment → Mastery 的既有链路影响下一次推荐。

## 4. 存储、隐私与故障语义

`review-actions-v1.json` 是唯一新增的持久化文件，位于插件已有隐藏目录：

~~~text
.vault-coach/
  recommendations/
    review-actions-v1.json     # 用户操作事实，schema 1
~~~

- 只保存 recommendation id、操作、时间、可选延后时间和可选注记；不复制笔记正文、chunk 文本、聊天记录或 API key。
- 读取或校验失败会显式报错，不会用空数组静默覆盖用户操作记录；Progress 在读取建议失败时仍显示其他已有本地事实。
- Recommendation snapshot、Progress snapshot 与 Markdown 计划都可重新生成；Markdown 仅经用户点击复制到剪贴板。
- 没有日历同步、提醒推送、遥测或外部服务请求。

## 5. 自动化验证

## 6. 手工验收清单

1. 在有 confirmed Concept、至少一场已保存考试的 Vault 打开 **学习仪表盘**，检查建议不超过 5 项，且原因与掌握度/到期状态一致。
2. 依次点击 **7 天后提醒**、**忽略**、**完成**，刷新/重启 Obsidian 后确认已处理项仍保留；在“已处理的建议”中点击 **恢复**，确认它重新回到待处理队列。
3. 点击 **查看来源**，确认打开的是当前有效 Concept 的笔记；更改图谱治理或重建后，不存在的来源必须失败提示而不是打开错误笔记。
4. 点击 **以此范围考试**，确认只进入普通考试设置、文件范围受限且仍可自行选择 simple/challenge；分析后尝试改模式，应继续遵守 M6 锁定行为。
5. 点击 **复制 Markdown 计划**，确认剪贴板权限失败时有清晰提示，成功时不在 Vault 中额外写入用户笔记。
