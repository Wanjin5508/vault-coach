# 商业模式、成本收益与用户增长策略

## 1. 商业命题

Vault Coach 的免费产品价值是“本地优先的知识问答、考试、图谱与学习证据”；Knowledge Engine 的商业价值是“免部署或高性能的持续计算”；AI Career Agent 的商业价值是“将经用户授权的能力证据转化为更可信的求职决策与训练”。

因此不应把图谱本身作为唯一付费墙。更可持续的付费理由是：省去部署和维护、支持更大规模、获得跨设备服务、完成长期任务，以及在用户授权后获得职业场景中的个性化结果。

```text
免费 Vault Coach Lite
        +
免费 Local Engine Docker（用户自己维护）
        +
付费 Cloud Engine（托管便利与可靠性）
        +
付费 Career Intelligence（职业闭环价值）
```

## 2. 产品分层与不可收费的底线

| 层级 | 建议提供内容 | 用户获得的价值 | 不应做的事 |
|---|---|---|---|
| Free / Lite | 本地问答、考试、基础确定性图、有限语义图、本地掌握度 | 零账号、离线、隐私、立即可用 | 不以强制上传 Vault 或广告换取使用权 |
| Free / Local Engine | 免费 Docker 镜像、文档、health check、可扩展索引与图计算 API | 数据不出本机、性能上限更高、可供高级用户集成 | 把难以维护的多个数据库手工安装步骤转嫁给用户 |
| Cloud Starter | 托管 Engine、基础同步、任务队列、健康监控、跨设备读取 | 不用 Docker、不用备份/升级、稳定运行 | 承诺无限模型/GPU 用量 |
| Cloud Pro | 更高工作区/计算额度、更大图谱、优先任务、历史与导出 | 对重度学习/研究用户有明确性能收益 | 用“节点数”等难理解指标制造付费焦虑 |
| Career Intelligence | 岗位—能力证据匹配、投递准备、个性化模拟面试、技能缺口计划 | 更高质量的职业行动结果 | 未经授权读取用户笔记或把模型推断伪装成事实 |

Local Docker 免费并不会削弱 Cloud 订阅：本地部署用户通常偏好隐私、控制与可定制；Cloud 用户支付的是安装成本、维护成本、跨设备、稳定性和职业工作流整合。

## 3. 定价策略

以下价格是首轮验证用的假设，不是当前承诺，也不应在未测算实际成本前公开。建议按“托管工作区 + 月度计算配额 + 职业工作流价值”定价，而不是按图节点数收费。

| 方案 | 建议月价（USD） | 主要配额/权益 | 目标用户 |
|---|---:|---|---|
| Lite | 0 | 本地功能与有界图谱 | 普通 Obsidian 用户、隐私优先用户 |
| Local Engine | 0 | 自托管高性能计算；用户承担机器与模型成本 | 开发者、研究者、家庭服务器用户 |
| Cloud Starter | 8 | 1 个个人工作区、受控同步/存储、基础异步任务 | 不愿运行 Docker 的个人用户 |
| Cloud Pro | 16 | 更高索引/任务额度、优先队列、更多历史与导出 | 大型知识库、持续学习用户 |
| Career Intelligence Bundle | 29 | Pro 能力 + 职位匹配、投递准备、面试模拟额度 | 正在积极求职的用户 |

定价的三个原则：

1. **不出售无限算力**：embedding、LLM、GPU/CPU 图计算均有可变成本；应按可理解的月度任务/同步/模拟额度限额，超额使用购买 credit 或自带 API Key。
2. **自带模型降低价格压力**：用户使用本地 Ollama 或自带兼容 API 时，云端只收取托管索引、任务与存储价值，不把模型成本混入无限套餐。
3. **年度订阅只在留存验证后推出**：可给予约两个月折扣，但不应在产品尚未验证价值前以低价年付换取短期现金流。

## 4. 成本模型与盈亏分析

### 4.1 成本类别

| 成本 | 固定/可变 | 控制手段 |
|---|---|---|
| 域名、官网、监控、基础控制面 | 固定 | 早期保持单区域、最小控制面 |
| 数据库/对象存储/备份 | 随工作区和保留期增长 | 默认只存必要同步副本；设置删除与保留策略 |
| CPU worker 与图计算 | 随任务增长 | 异步队列、节点/边预算、缓存、任务额度 |
| embedding / LLM / GPU | 高度可变 | 本地模型、自带 Key、批处理、限额与 credit |
| 带宽与日志 | 随同步和访问增长 | hash 增量同步、不上传完整 Vault 快照、日志脱敏 |
| 支付、客服、文档与运维 | 随付费用户增长 | 自动诊断、Docker health check、清晰限制与支持分层 |

不要在早期同时维护 PostgreSQL、Neo4j、Qdrant、Redis 和多套 worker。多数据库会把备份、迁移、观测、Docker 编排与故障恢复成本放大，常常比“查询慢一点”更早消耗个人开发者的时间。

### 4.2 单位经济模型

使用以下公式，而不是在没有真实用量前假装精确计算：

```text
每用户贡献毛利 = 月订阅收入
              - 支付渠道费
              - 该用户的存储、带宽、计算、模型与支持可变成本

月度盈亏平衡付费用户数 = 月固定成本 / 平均每付费用户贡献毛利
```

首轮预算可使用如下**规划假设**做敏感性分析：支付费率 5%，Starter/Pro/Career 的平均可变成本分别为 USD 1.60 / 3.50 / 8.00。

| 方案 | 月收入 | 支付费（5%） | 假设可变成本 | 单用户贡献毛利 |
|---|---:|---:|---:|---:|
| Starter | 8.00 | 0.40 | 1.60 | 6.00 |
| Pro | 16.00 | 0.80 | 3.50 | 11.70 |
| Career Bundle | 29.00 | 1.45 | 8.00 | 19.55 |

例如月固定成本为 USD 200 时，若用户结构单一，约需 34 位 Starter、18 位 Pro 或 11 位 Career Bundle 用户达到当月盈亏平衡。真实结果将强烈受模型调用、用户活跃度、存储策略和人工支持时间影响；Cloud beta 上线后应每月按真实工作区统计更新此表。

### 4.3 何时提供 Cloud

不是“有服务器就上线”，而是在以下条件同时满足后启动小规模 beta：

- Local Engine 已有可重复的安装、升级、故障诊断与备份流程；
- 有一组设计伙伴明确表示愿为免部署、跨设备或职业联动付费；
- 已测得单个活跃工作区的存储、同步、图计算、模型和支持成本；
- 已具备同步范围选择、删除、撤销、导出与故障恢复能力；
- 不把 Cloud 的可用性作为 Lite/Local 功能的前提。

## 5. 用户增长策略

### 5.1 先验证激活，不急于转化

最先优化的不是付费页，而是如下激活链路：

```text
安装插件
  → 成功索引一个范围
  → 得到一次有来源的回答
  → 完成一次考试并保存证据
  → 打开 Learning Map / 得到掌握度结果
  → 发现 Local Engine 或 Cloud 的规模价值
```

应记录匿名、可关闭的产品事件，或优先使用本地可导出的诊断报告；不要收集笔记内容。核心漏斗指标包括：

- 安装到首次成功索引的转化；
- 首周完成问答、考试、Learning Map 的比例；
- D7/D30 活跃与索引重建成功率；
- 达到容量阈值后尝试 Local Engine 的比例；
- Local Engine 试用到 Cloud 付费的比例；
- Career Bundle 的“职位匹配 → 面试模拟 → 真实投递行动”完成率。

### 5.2 免费增长渠道

- Obsidian 社区插件目录、GitHub README、可复现实例 Vault；
- 面向开发者/研究者的“本地 RAG + 考试证据 + 学习图谱”教程；
- Local Engine 一键 Docker 文档、故障排查与基准测试；
- 将用户可导出的匿名性能诊断转化为公开 benchmark，而不是收集 Vault；
- 与开源职业工具、学习社区和技术内容创作者合作演示工作流。

### 5.3 职业产品的增长闭环

Career Agent 不应把 Vault Coach 用户自动导入营销漏斗。正确路径是：用户在 Vault Coach 内主动发布 `KnowledgeProfile`，并理解该画像将用于“职业个性化”；Career Agent 再提供可解释的岗位匹配、能力缺口和面试训练。

这会形成正向循环：

```text
学习证据 → 能力画像 → 更准确的岗位/面试建议
      ↑                              ↓
      └──── 个性化复习与项目准备 ────┘
```

## 6. 风险与防护栏

| 风险 | 后果 | 防护措施 |
|---|---|---|
| 过早引入多数据库/微服务 | 运维复杂度超过产品价值 | 先模块化单体；仅按测量瓶颈拆分 |
| Cloud 同步范围不清 | 用户不信任、隐私风险 | 明示范围、逐项授权、可撤销、可删除 |
| 免费 Docker 支持成本过高 | 个人开发者被安装问题淹没 | 支持官方单一 Compose、健康报告和社区文档；高级人工支持可收费 |
| 模型成本不可控 | 订阅亏损 | 不提供无限额度；任务配额、自带 Key、credit、缓存 |
| Career Agent 越界读取 Vault | 产品信任受损 | 只消费授权的 KnowledgeProfile，不直连 Vault |
| 图谱好看但不产生行动 | 留存低 | 连接考试、掌握度、复习和职业决策，持续验证行动指标 |

## 7. 12 个月优先级

1. 完成 Vault Coach 的本地价值闭环：Learning Map、掌握度展示、复习/学习路径的最小实现。
2. 固化 `KnowledgeEngineClient` 与版本化数据契约，但不让服务成为基础功能的硬依赖。
3. 发布免费 Local Engine alpha，优先解决安装体验、增量同步、ANN 和大图任务。
4. 以设计伙伴验证 `KnowledgeProfile` 与 Career Agent 的职业结果是否真的更准确、更可解释。
5. 在掌握成本与付费意愿后，发布小规模 Cloud beta；以 Pro 与 Career Bundle 检验单位经济。
6. 仅根据真实负载决定是否拆分检索、图计算或 embedding worker。

## 8. 需要在发布前单独决策的事项

- Local Engine 镜像、服务端源码和 Cloud 附加服务的许可证边界；
- 是否允许自带 OpenAI-compatible/Ollama 模型，以及相应支持范围；
- Cloud 的数据驻留区域、备份周期、删除窗口和事故响应流程；
- 付费模型是纯订阅、订阅 + credit，还是 Career Agent 单独计费；
- 用户画像在两个产品间的授权文案、可见性和撤销体验；
- 与专业人士核对隐私、数据处理、付款、税务和职业建议相关义务。

本文件是产品与财务规划假设，不构成法律、税务或投资建议。所有价格、成本和转化假设都应在 beta 的真实数据上复盘。
