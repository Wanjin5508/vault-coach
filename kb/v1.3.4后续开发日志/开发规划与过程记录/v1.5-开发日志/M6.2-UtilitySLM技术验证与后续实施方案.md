# M6.2：Utility SLM 技术验证与后续实施方案

## 1. 结论先行

下一切片只做 **生成模型候选固定与可重放技术实验**，不直接接入设置、默认路由或用户记忆写入。

- 第一候选：`onnx-community/Qwen2.5-0.5B-Instruct`。上游 `Qwen/Qwen2.5-0.5B-Instruct` 为 0.49B 参数、Apache-2.0；模型卡声明支持包括中文、英文、德文在内的 29+ 语言，并强调结构化/JSON 输出能力。ONNX 仓库明确标注 Transformers.js text-generation 兼容。
- WASM 主实验 dtype：`q8`，对应当前 Transformers.js 4.3.1 的 `_quantized` 文件映射。WebGPU 对照：`q4f16`；它不能替代 WASM 证据。
- 英文资源对照：`onnx-community/SmolLM2-360M-Instruct-ONNX`。其模型卡明确说明主要理解和生成英文，因此不能凭更小体积成为中文默认候选。
- 暂缓：`onnx-community/gemma-3-270m-it-ONNX`。其体积和多语言声明有吸引力，但上游使用 Gemma 条款且 Hugging Face 原仓库要求接受许可；当前 ONNX 还使用 external-data 多文件形态。许可证、授权 UX 和资产加载都需单独评审。
- 暂不纳入第一轮：Qwen3 0.6B。它更大，且 thinking/non-thinking/chat-template 行为增加了本阶段不需要的输出变量。

以上是 **实验优先级**，不是模型 GO 或默认策略。模型卡的 JSON/多语言声明必须由 Vault Coach 冻结样本重新验证。

## 2. 已确认的实现基础

仓库实际安装 `@huggingface/transformers@4.3.1`。本地源码核对结果：

- `Qwen2ForCausalLM`、`Qwen3ForCausalLM`、`Gemma3ForCausalLM` 已注册到 `AutoModelForCausalLM`；
- `TextGenerationPipeline` 对 chat 输入调用 tokenizer 的 chat template，并默认只返回新增 assistant 内容；
- `TextStreamer({ skip_prompt: true })` 可只流出新 token；
- `InterruptableStoppingCriteria` 可在下一 token 边界软取消生成；硬取消仍由现有 Worker epoch/terminate 机制负责；
- dtype 映射中 WASM 默认 `q8 → model_quantized.onnx`，`q4f16 → model_q4f16.onnx`。

这只证明锁定依赖具有相应 API/架构入口。是否能在 Obsidian Worker 加载候选、是否支持所选算子、是否满足内存和延迟预算仍需实测。

## 4. Utility task policy v1

### 4.1 Query rewrite

输入：system prompt、知识范围、原问题、按最近消息截取的对话上下文。

建议初始预算：

| 项目 | v1 提案 |
| --- | --- |
| prompt 总上限 | 1024 tokens |
| 原问题 | 最多 192 tokens；尾部不静默丢弃否定/时间条件 |
| 对话上下文 | 最多 640 tokens，按完整 message 从新到旧装入，再恢复原顺序 |
| scope | 最多 128 tokens |
| `max_new_tokens` | 96 |
| decoding | `do_sample: false`、`num_beams: 1`；不设置 temperature |
| 输出 | 仅 `{"rewritten_query":"..."}` |
| 修复 | 第一轮不做模型二次 repair；校验失败直接使用原问题 |

prompt 必须要求保留实体、否定、时间、范围、版本号、路径和缩写；不得回答问题、扩大知识范围或引入新事实。模型返回合法 JSON 仍须通过 [[里程碑6.2-UtilitySLM与辅助任务路由]] 已实现的 contract v1。

### 4.2 Memory extraction

输入必须用明确的 `user`/`assistant` 标签区分本轮文本。模型只生成候选，不能直接写存储。

| 项目 | v1 提案 |
| --- | --- |
| prompt 总上限 | 2048 tokens |
| 历史上下文 | 最多 768 tokens |
| 最新 user | 最多 384 tokens |
| 最新 assistant | 最多 640 tokens；只作为上下文，不得把助手推测写成用户事实 |
| `max_new_tokens` | 192 |
| decoding | `do_sample: false`、`num_beams: 1`；不设置 temperature |
| 输出 | 仅 `{"memories":["..."]}` |
| 数量/长度 | 最多 5 条，每条最多 500 字符 |
| 修复 | 第一轮不 repair；失败返回空候选，既有记忆不变 |

后续提交层还要验证开关、session/turn、task epoch、取消状态和幂等性。模型 schema 成功不能授权写入。

### 4.3 Prompt 与策略身份

以下任一变化必须递增 `utilityTaskPolicyVersion`，但不得重建 embedding 索引：

- system/user prompt；
- chat template 或 tokenizer；
- 输入截断策略；
- `max_new_tokens`、decoding 参数；
- JSON schema、validator 或 memory 业务规则；
- 模型 revision/dtype。

## 5. 实施阶段与 Gate

### Phase A：资产清单和 Node CPU 最小实验

新增显式脚本，不修改生产路由：

```text
scripts/spikes/local-ai/utility-smoke.mjs
scripts/spikes/local-ai/utility-contract-smoke.mjs
benchmark-results/local-ai/utility-smoke-<run-id>/
```

要求：

1. `--allow-download` 默认为 false；只有显式授权才下载固定 revision。
2. 下载后逐文件校验大小和 SHA-256；离线独立进程必须能重载。
3. 使用模型自带且已哈希的 chat template，不在代码中偷偷替换另一模板。
4. 对 zh/en/mixed rewrite、正/负 memory 各至少一例执行 `do_sample:false` 生成。
5. 只解析新增 token；同时记录 prompt token、generated token、tokens/s、首 token、总延迟和 RSS，不落盘正文。
6. 使用现有 strict validator；输出无效时结果为 FAIL，不在实验脚本里宽松清洗。
7. Node smoke 只证明 API/资产/最小输出方向，不得写 Worker PASS 或质量 GO。

Phase A 停止条件：无法固定资产、chat template 不兼容、单例仍频繁输出非 JSON、WASM/CPU 内存明显超过预算，或许可证无法接受。

### Phase B：独立 Obsidian Worker smoke

在 production 路由之外扩展 smoke plugin，再决定是否改 `LocalAIRuntime`：

- 同一个 Worker 中加入 `utility` role，复用 ORT、scheduler、缓存和 epoch；不得新建第二套下载器。
- 首轮只跑 WASM/q8，因为当前生产 Worker 明确固定 WASM。WebGPU/q4f16 是独立能力矩阵，不能用其 PASS 覆盖 WASM FAIL。
- `InterruptableStoppingCriteria` 连接 soft cancel；超时或无法在 token 边界退出时 hard-cancel 整个 Worker，所有 pending 请求按 epoch 拒绝。
- 角色切换顺序固定为 Utility → Embedding → Reranker，记录每次 unload/reload；任一失败不得留下错误 `ready` 状态。
- 验证在线准备、断网重启、缺文件、哈希错误、取消、Worker crash、缓存清理和插件卸载。
- trace 只含 task、policy、token count、latency、状态和错误码，不含 prompt/output。

Phase B 通过前不得创建 `BuiltinUtilityProvider` 的用户可达路由。

### Phase C：冻结数据集与离线质量 Gate

建立两个独立数据集，禁止用一个“结构成功率”替代两项业务判断：

```text
benchmarks/local-ai/utility/rewrite-v1.jsonl
benchmarks/local-ai/utility/memory-v1.jsonl
benchmarks/local-ai/utility/prompts/v1/
```

Rewrite 切片至少包含 zh/en/mixed、指代、省略、否定、时间、版本号、路径、技术别名、无须改写和 prompt injection。每例包含 `must_preserve`、`must_not_add` 和固定检索候选/相关性标签。

Memory 切片至少包含稳定偏好、长期项目、明确目标、持续约束、一次性请求、助手推测、用户否认、跨轮冲突、无候选和 prompt injection。每例包含允许候选和禁止候选；人工标签必须去隐私、版本化。

预登记建议门槛见 `benchmarks/local-ai/protocol.json`。首次 acceptance 结果产生后不得修改同一版本门槛或标签来制造 GO。

### Phase D：应用 adapter 与安全提交

仅在 Phase A–C 有证据后实施：

1. `LocalAIRuntime` 增加窄 `LocalAIUtilityRuntimePort`，不增加万能 `generate()`。
2. `BuiltinUtilityProvider` 分别实现 rewrite/memory task policy，输出先 strict parse，再通过现有 guard。
3. `UtilityRouter` 对两个任务分别选择 `local | existing-chat | disabled`；一次任务冻结 route/policy。
4. local 失败不得自动调用 existing chat/cloud；rewrite 回原问题，memory 跳过。
5. MemoryService 在提交点二次核对开关、turn/session/epoch 和取消；清空/关闭后迟到结果不可回写。
6. 完成故障注入后才接 M7 状态卡片；下载完成不自动启用。

## 6. 预登记指标与建议门槛

以下数字为首次实验前的提案，状态保持 `pending-owner-approval`：

| 指标 | 建议门槛 |
| --- | --- |
| strict schema success | rewrite 与 memory 各 ≥ 98% |
| rewrite 关键实体/否定/时间保留 | 每切片 ≥ 98% |
| rewrite 无依据新增事实率 | ≤ 1% |
| rewrite NDCG@10 | 平均相对原问题提升 ≥ 0.02；任一语言退化 ≤ 0.01 |
| memory precision | ≥ 98% |
| memory acceptance false write | 0；任一禁止候选进入提交层即 NO-GO |
| memory recall | ≥ 70%；不得用降低 precision 换取 |
| desktop WASM rewrite p95 | ≤ 8 s |
| desktop WASM memory p95 | ≤ 12 s |
| warm role restore p95 | ≤ 5 s |
| desktop peak memory | ≤ 1024 MiB |
| 模型总下载 | ≤ 600 MiB |

WebGPU 指标单列设备/驱动/Obsidian 版本；不能与 WASM 混合计算。移动端在未测前保持 `pending`，不显示可用。

## 7. 故障矩阵

| 故障 | 预期结果 |
| --- | --- |
| 模型未安装/离线缺文件 | rewrite 原问题；memory 空候选；不外发 |
| JSON 非法/多字段/超预算 | strict validator 拒绝；不 repair、不部分接受 |
| soft cancel | 下一 token 边界停止；结果不提交 |
| timeout/推理卡死 | hard-cancel Worker；epoch 失效；其他 pending 一并失败 |
| Worker crash/OOM | role 进入 error/evicted；原回答链继续可降级 |
| Utility→Embedding 切换失败 | 不保留虚假 ready；可从缓存重新准备上一角色 |
| 用户关闭 rewrite | 不创建 Utility 任务 |
| 用户关闭/清空 memory | 进行中任务失效；迟到结果不回写 |
| local provider 失败 | 禁止静默调用现有 chat/cloud provider |
| trace/benchmark | 不记录 query、conversation、memory 或生成正文 |

## 8. PR 切分

1. **M6.2-A Candidate + Node smoke**：冻结 Qwen2.5 revision/资产；实现显式下载、离线重载、两类最小生成和结果报告。
2. **M6.2-B Worker feasibility**：独立 smoke plugin 的 Utility role、soft/hard cancel、角色切换和故障矩阵。
3. **M6.2-C Dataset + quality report**：冻结 rewrite/memory 数据集、评测器和 GO/NO-GO；不改生产路由。
4. **M6.2-D Adapter + rewrite route**：本地 rewrite adapter/router；失败用原问题；比较端到端检索收益。
5. **M6.2-E Memory transaction**：候选→验证→提交状态机、迟到结果和幂等保护。
6. **M6.2-F Settings + M7/M8/M9**：分别启用、清理、迁移、隐私文案和发布 Gate。

每个 PR 必须可独立回退。若 Qwen2.5 在 Phase A/B 资源 NO-GO，可保留 contract/guard，转测 Gemma/SmolLM；若质量 NO-GO，则 rewrite 默认关闭、memory 不启用，本阶段不阻塞现有 RAG。
