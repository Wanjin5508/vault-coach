# Vault Coach 1.5 后续开发路线：逐步内置 AI 基础设施

## 1. 本轮规划依据与当前状态

直接依据：[[VC知识库总览/专题教程-内置LLM运行时/06-实现顺序|06-实现顺序]]。产品主线调整为：

> Embedding → Reranker → Utility SLM → 可选的主生成 LLM。用户选择知识范围，按需准备本地模型，再连接自己喜欢的主 LLM。

这里的“四个模型”是四类职责，不要求四个模型同时常驻，也不要求全部完成后才发布。首次准备需要下载授权；权重准备好且设备通过验证后才承诺离线推理。

2026-10-23 静态核对：根目录 manifest/package 仍为 1.5.2，最低 Obsidian 1.11.4，支持移动端声明；依赖中尚无 Transformers.js。M2/M2.1 的设置分层、范围选择和 UI 偏好已存在；M3 的新 provider/索引代际与统一 LocalAIRuntime 尚未实现。当前代码中 rewrite/memory 仍属于 ChatProvider，rerank 是可选远程调用或启发式降级。

此次只更新规划；文中的新路径、接口和测试是待实现设计，不代表已通过运行验证。旧 M3 中的历史测试记录保留原日期，不作为今天的验收结果。原 M4–M9 与总览保存在 [[历史规划-2026-10-23调整前/README|历史规划]]。

## 4. 需要修正的产品假设

- Embedding/Reranker 是 encoder 类职责，Utility/Main Chat 是生成职责，输入输出与预算不能用一个通用 `generate()` 模糊处理。
- M6.1 完成只能证明召回和重排可本地执行。当前 rewrite 使用聊天模型，若配置云端，查询前处理仍会外发。完整本地检索前处理需要 M6.2 本地改写，或用户关闭改写。
- “只配一个主 LLM API”是减少配置项的目标。主回答、考试和目前的概念抽取仍可能向选定服务发送内容。
- “200M–600M”“三模型不到 1 GB”是探索范围与体积预算假设，不是质量或设备支持的结论；模型下载字节与峰值运行内存分开测量。
- 小输出不保证任务简单。中文改写忠实度、记忆无捏造和 JSON 校验必须单独评估。
- WebGPU → WASM 只在同一模型策略可用且预算允许时回退；若 dtype/模型改变导致 embedding 空间变化，必须走 M3 失效流程。
- 不在插件启动时自动下载。用户点击“准备本地搜索”并看到来源、大小、用途后，程序可自动完成后续步骤。

## 5. 实施与协作方式

每个步骤采用：行为刻画 → 最小端口 → adapter → consumer → 故障注入 → 实机验证。单次 PR 聚焦一个可验证边界；详细范围见各里程碑。不要求为纯文案或机械变更编写重复测试。

开始前记录工作区与基线：

```bash
git status --short
git rev-parse HEAD
node --version
npm --version
npm ci
npm run lint
npm test
npm run build
```

在自己的实现分支执行，保护用户未提交改动；当前文档编辑没有执行这些代码门禁。源文件路径以本文核对结果为起点，新建路径在各文档标注“拟新增”。

每个 PR 记录：问题、输入输出契约、数据影响、内部/外部依赖、验证命令和结果、设备证据、失败恢复、下一步输入。没有实际执行的项目写“未执行”，不能填 PASS。

| 阶段 | 工程技能 | 必须留下的证据 |
