# 里程碑 6.1：内置 Reranker 与检索质量验证

## 1. 目标与边界

在已有召回候选上增加本地 Cross-encoder 重排，减少用户配置外部重排服务的需要。沿用 [[01-LocalAIRuntime架构与跨里程碑契约]] 的运行时、资源缓存、Worker 与调度，不为重排再创建一套下载器。

Embedding 将文本分别编码为向量以支持快速召回；Cross-encoder 联合处理 query/document 对，为少量候选计算相关性。因此重排只能改善已召回候选的顺序，不能找回被候选截断提前丢掉的文档。[原理与使用场景：Sentence Transformers](https://sbert.net/examples/cross_encoder/applications/README.html)

交付范围：一种经评测通过的本地模型、现有远程与启发式兼容路径、明确候选预算及降级。暂不引入主聊天模型、通用多跳检索或训练流水线。M6.3 可复用本阶段的稳定候选 ID、source locator 和重排端口，但 GraphRAG 的图扩展与证据融合不属于本阶段。

> [!status] 2026-11-05 实现状态
> 已完成契约基线、固定候选模型的 Node CPU 最小实验、共享 Worker/调度/缓存运行时的 Reranker 角色骨架，以及严格结果校验和回归测试。当前仍为 **experimental / 未接入用户设置 / 未进入默认检索路由**。实际 Obsidian Worker 推理、冻结评测集、目标设备性能和正式 GO/NO-GO 尚未完成，因此本里程碑不能标记完成。

## 4. 按顺序实现

### Step 1：冻结旧行为与候选语义

阅读 rag-engine 的 rerankCandidates/remoteRerank：当前先按 rerankTopK 截断，远程使用 index/relevance_score；失败走启发式；混合分数目前是重排分数加原分数的 0.05 倍。这是基线，不代表适用于新模型。

- 记录 rerankTopK 是进入重排的候选上限，contextTopK 是最终上下文数量，不能借迁移悄悄改变旧设置含义。
- 写重复 ID、空列表、少量候选、远程失败的行为刻画；保存同一查询的召回结果作为后续固定输入。
- 定义业务候选 ID 到 provider batch index 的单次请求映射。不要把分批后的局部 index 当全局 ID。

**依赖/交付：** M3 adapter 与候选类型；产出输入输出样例和兼容性测试。

### Step 2：做最小模型实验，再决定输出解释

- 固定模型 revision、dtype、max sequence length 和 tokenizer。
- 用一条 query 配三篇可判别相关性的文档跑通；检查输出形状、标签映射、是否单 logit、是否需要 sigmoid/softmax。
- 不假定 Transformers.js 存在可直接使用的通用 rerank pipeline；根据所选模型确认序列分类接口、pair tokenization 与输出解释。
- 在实际 Worker 上测冷启动、热运行、WASM/WebGPU 支持和峰值内存，再接入完整服务。

**外部依据：** [Transformers.js 模型 API](https://huggingface.co/docs/transformers.js/v3.8.1/en/api/models)。接口可用性以 M4 锁定版本为准，不能只凭模型名称推定支持。

### Step 3：实现 token 预算与调度

- 先给 query 预留 token，再给文档分配余额；记录截断数量，避免 query 被长文挤掉。
- batch size 由 M4/M6 的实测预算决定；每批检查 AbortSignal。
- 复用共享调度器：召回完成后释放 embedding lease，再申请 reranker；不要持有两个独占 lease 相互等待。
- 初版按有限候选工作；长文多窗口重排仅在预登记额外成本后尝试，记录 max/mean 聚合策略。
- 将候选数量、截断策略、score transform 计入任务策略版本；这些变化不使现有 embedding 向量失效。

**交付：** 无模型重复常驻、可取消、候选不丢 source 的 adapter。

### Step 4：整合排序与可预期降级

- 校验 ID 属于本次请求、无重复、分数有限；NaN、越界 index、缺少必要候选视为无效响应。
- 建议首版本要求所有传入候选都有分数；若支持远程 top-N 响应，必须独立定义未返回项规则，不能统一补 0 当真实相关性。
- 本地分数尺度与旧远程不同，默认先按校验后的重排分数排序；平分用原排序。是否混合原分数必须有离线评测依据。
- 模型未准备、超时、OOM 或输出无效时，回退到已定义的原召回/启发式路径；记录原因码。
- 内置失败不能自动调用云端。旧用户明确选择远程的配置继续按旧路径工作。

**交付：** 一个服务入口；知识来源引用始终来自原候选，而非模型生成的文本。

### Step 5：用冻结样本比较，决定是否默认启用

对照至少包含：原召回、现有启发式、候选本地模型。固定召回候选后比较 NDCG@K、MRR@K 和上下文相关性；同时独立检查候选 Recall@N，区分召回失败和重排失败。

按中文、英文、混合语种、长文截断、近义干扰分组。记录 p50/p95 延迟、首次加载、模型切换成本、峰值内存、失败率和实际下载字节。较少候选与较多候选分别测试，不用一次“看起来不错”的回答替代指标。

在实验前填写具体数字：质量提升下限、关键语种退化容忍、p95 上限、内存上限。未填写门槛或未跑实机只能保持 experimental，不能写 GO。

### Step 6：接入设置与故障提示

复用 M7 准备卡片，显示模型大小、来源、状态；高级设置可选择重排策略。启用开关与模型准备状态分别存储，下载完成不擅自覆盖用户选择。发布前进入 M7 → M8 → M9。

- [ ] 质量与设备门槛有实际数据，默认策略按平台决定。
- [x] Reranker 策略与 embedding fingerprint 分离；Reranker trace 测试确认不记录 query/正文。

回退时关闭本地重排路由，保留缓存供用户选择清理，不删除索引、不偷偷选择远程服务。若收益不足，保留 provider 接缝与实验结果，先交付 Embedding。

## 6. 新人协作与开发记录

建议 PR：契约与基线 → 最小模型实验 → adapter/调度 → 路由与排序 → 评测/设置。每个 PR 说明分数含义、失败路径与证据，reviewer 应能重放相同候选而无需访问作者私有 Vault。

### 2026-11-05：首个实现切片

1. **契约与旧行为基线**
   - `RerankProvider` 现在拒绝空 ID 和重复候选 ID；legacy adapter 保持远程协议，并对空候选短路。
   - 新增旧 RAG 行为测试，覆盖 `rerankTopK`、稳定 ID 映射、禁用时顺序、远程失败启发式降级和空召回。
   - 新增 `BuiltinRerankProvider`，只负责将领域候选映射到共享本地运行时，不直接改动 `rag-engine` 或设置。

2. **固定实验候选**
   - 候选：`SugoLabs/mmarco-mMiniLMv2-L12-H384-v1`，revision `6772eee1ea62dc82e1fcaaf3ed90c269fdcb1fcf`，`onnx/model_quantized.onnx`，单 logit、identity score。
   - registry 固定 tokenizer/config/model 的 SHA-256；总资产约 129 MiB，最大序列 256 tokens，query 最多预留 64 tokens，实验 batch size 8。
   - Node 20 CPU 最小样本结果：加载约 1092 ms，三对推理约 25 ms，相关文档得分 `-1.0799` 并排第一；进程 RSS 约 625 MiB。这里只证明 Node API、模型文件和输出方向可用，**不等价于 Obsidian Worker 或目标设备通过**。
   - 可重放命令：`npm run m6.1:smoke:reranker -- --model-path=<已校验模型目录>`；结果写入 gitignored 的 `benchmark-results/local-ai/`。

3. **共享运行时骨架**
   - Embedding 与 Reranker 共用一个 Worker、ORT 资源、缓存下载校验和前台调度器；角色切换先释放当前模型，并把另一角色标记为 `evicted`，避免两个模型重复常驻。
   - Reranker 在 Worker 内按 query/document pair tokenize，先保留 query 预算，再截断 document；每批检查取消，输出必须恰好覆盖本次所有候选且每项只有一个有限分数。
   - 主线程再次校验 role、policy、epoch、job、候选 ID、重复/缺失/未知项；trace 只记录数量、延迟和状态，不记录正文。

4. **本切片验证**
   - ESLint、TypeScript、生产构建和发布资产校验通过；`main.js` 2,917,268 bytes，低于 4,500,000 bytes 预算。
   - Vitest：76 个测试文件、330 个测试全部通过。

5. **仍需完成**
   - 在真实 Obsidian/Electron Worker 中验证在线准备、断网重载、角色切换、取消、OOM/崩溃降级。
   - 冻结中文、英文、混合语种、长文和近义干扰样本，按预登记的 NDCG/MRR、p95、内存及下载门槛运行正式比较。
   - 在正式 GO 后再实现统一 rerank service、设置项和默认路由；内置失败不得静默调用云端。

本切片结论：继续保持 **experimental / NO DEFAULT**，不是 M6.1 完成或模型 GO。GraphRAG 后续入口见 [[里程碑6.3-GraphRAG问答与考试增强]]。
