# M6.2-A3：候选筛选与许可决策开发日志

## 1. 目标与边界

本次从 q8/q4 NO-GO 证据继续，只做当前小模型的多语言、许可证、资产体积、Transformers.js 架构和 WASM 前置可行性筛选。分支为 `codex/m6-2-utility-slm-candidate-decision`。

本阶段没有下载任何新模型权重，不创建 production Utility policy，不进入 Worker，不改变路由、设置或默认值。许可证选择属于负责人决策，不能由技术筛选自动接受。

## 2. 新增可校验资产

新增 `benchmarks/local-ai/utility-candidate-screening.json`，记录：

- 不可变 ONNX revision；
- 远端 manifest 的量化主图/external-data 字节数与 SHA-256；
- 运行所需小文件和总字节估算；
- 语言、架构、锁定 Transformers.js 注册状态；
- 许可证状态、阻塞项和决策；
- `downloadAuthorized:false`、`workerPhaseAllowed:false`。

`scripts/spikes/local-ai/validate-local-ai-assets.mjs` 现在同时校验该筛选账本与 `protocol.json`、`package.json`：下载门槛、依赖版本、40 位 revision、语言覆盖、逐文件字节合计和远端大文件 SHA-256 必须一致。

### 4.1 LFM2.5-350M

技术上最接近需求：模型卡声明 English、Arabic、Chinese、French、German、Japanese、Korean、Portuguese、Spanish，并把 data extraction、structured outputs 和 tool use 列为推荐场景。ONNX 仓库标记 Transformers.js text-generation；锁定依赖源码已注册 `lfm2 → Lfm2ForCausalLM`。

q4 使用 `onnx/model_q4.onnx` 与 `onnx/model_q4.onnx_data`，不是单文件。当前 production 下载器可通过 `files`/`assetSha256` 表达额外文件，但尚无 Utility policy，也没有证明 Transformers.js 4.3.1 在 Obsidian WASM 中能正确恢复 external data，因此只能进入 Node smoke，不能直接进入 Worker。

许可阻塞：LFM Open License v1.0 允许广泛使用和分发，但商业使用权受年营收 1000 万美元阈值约束；超过阈值需另购商业许可。分发时还需提供/链接许可证并保留相应 notice/attribution。该条件不是 Apache-2.0 等价物。

### 4.2 Gemma 3 270M IT

体积和语言覆盖满足预筛，锁定依赖也已注册 Gemma 3。不过 Gemma Terms 要求后续用户收到协议和使用限制，非 hosted distribution 还需要 Notice；上游 Hugging Face 访问要求接受条款。若选择它，需要设置/下载 UX、NOTICE、清理与再分发设计，不能直接拿公开 ONNX URL 绕过上游接受流程。

### 4.3 SmolLM2-360M Instruct

资产和 Apache-2.0 初筛简单，但上游明确模型主要理解和生成英文。它不能为中文和德文默认能力提供证据，仅保留为英文资源/性能 control。

## 5. 决策

当前状态：**LFM2.5 conditional shortlist / blocked on owner license decision**。

负责人需要三选一：

1. 接受 LFM Open License v1.0 的营收门槛与分发义务，授权 A4 下载固定 q4 资产并执行 Node smoke；
2. 不接受 LFM，转入 Gemma Terms 与分发 UX 决策；
3. 两者都不接受，结束 v1.5 内置 Utility SLM 路线，保留 existing-chat/disabled 和已实现的严格 guard。

任何选择都不构成生产 GO。A4 若执行，仍须重新通过 contract、语义、false-write、RSS、离线 external-data 和无网络请求证据。
