# 里程碑 10：可选内置主生成 LLM 技术验证

## 1. 为什么单独立项

用户主线是内置 Embedding、Reranker、Utility，同时允许选择更强的 Ollama/云端主 LLM。主生成质量、长上下文、流式输出和资源需求与短文本辅助任务不同，因此本阶段是可选实验，不阻塞增量 A/B/C 发布。

Utility SLM 跑通短 JSON 不能作为它能胜任知识问答的证据。可以实验同一模型复用权重，但仍需不同任务策略与独立质量 Gate。不开启本阶段，产品仍可完成前述目标。

## 2. 前置依赖

- 内部：M3 ChatProvider 与辅助任务的职责已分离；M4–M6 的生成运行位置、资产分发、取消和资源预算已有证据；M7–M9 可重复验收。
- 外部：候选模型许可、ONNX/量化版本、chat template、tokenizer、上下文上限、所需算子和设备支持。
- 产品：明确目标设备、可接受下载/内存/首 token 延迟、回答质量门槛与启用方式；这些数字要在试验前填定。
- 测试数据：固定 RAG 资料、问题和引用依据，覆盖中文/英文、多来源冲突、资料不足及长上下文。

无需为此依赖远程 Knowledge Engine。若设备无法承受，再另立服务运行方案 ADR，不能在同一实验中悄悄改成后台云推理。

## 3. 变更地图

| 文件/模块 | 计划 |
| --- | --- |
| src/domain/model/chat-provider.ts | 核对拆分后的主生成契约；不重新塞入 rewrite/memory |
| src/infrastructure/model/builtin-chat-provider.ts（拟新增） | 生成/流式适配，输出和停止原因 |
| src/app/application-container.ts | 显式选择内置或外部 provider |
| src/infrastructure/local-ai/、src/app/local-ai/（前置拟新增） | 复用资源设施；为长生成制定独立调度与预算 |
| src/app/config/settings-*、src/settings.ts、M7 setup | 可选开关、实际能力说明，不覆盖已有主 LLM |
| benchmarks/local-ai/chat/（拟新增） | RAG 回答质量、资源和端到端报告 |

共享资源管理不等于共享业务接口。主生成与 Utility 不应互相调用来掩盖职责和失败路径。

## 4. 新人实施顺序

### Step 1：先验证一个有引用的最小 RAG 回答

固定资料和问题，用非流式生成确认 chat template、stop token、上下文预算和解码。记录事实正确率、引用可核对性、资料不足时的回答表现；模型能吐字仅是 smoke，不算产品可用。

### Step 2：再加入 token 预算与流式协议

为系统指令、用户问题、历史和检索片段分配明确预算，并预留输出空间；不能简单按字符数假定 token 数。保留来源映射，不让截断把引用指向错误片段。

定义增量 delta、最终结果、取消、超时、错误与 finish reason。保证取消后不再写 UI，卸载释放会话/KV cache；partial answer 不当成完整成功写入后续记忆。

### Step 3：验证资源竞争与长任务响应

测冷启动、首 token、tokens/s、总耗时、峰值内存和长上下文增长。与后台索引、重排、Utility 交替运行，调度器必须限制同时加载，明确长生成期间其他任务如何排队/取消。

不能直接套用短 Utility 任务的超时；也不能为主生成无限延长所有任务预算。OOM 后清理资源并提示，绝不把本地用户问题自动转发云端。

### Step 4：主回答与其他生成能力分别验收

先支持明确范围的聊天回答。考试评价、JSON 输出、概念抽取等现有调用另测；如果内置模型不能支持某项操作，应显示能力限制或要求用户明确选择外部 provider，不能暗中切换。

若先只实现部分 ChatProvider 方法，需要在能力声明和调用前检查中表达，不提供“看似成功”的占位输出。

### Step 5：独立决定 GO/NO-GO

每种设备和用途单独决定。只有质量、响应性、隐私和发布资产全通过后，才进入 M7–M9。初版建议显式 opt-in，默认仍尊重用户既有主 LLM。

NO-GO 时保留实验报告、复现脚本和失败原因；前面三个角色继续发布。模型升级或新设备出现后再用相同样本复测，避免凭一次演示推翻结论。

## 5. 交接与记录

交付应包含候选矩阵、明确数字门槛、实验代码、模型/依赖锁定、质量和资源报告、设备范围、流式/取消证据及 ADR。当前仅规划，未选模型、未实现、未实机验证，也不预先承诺归入某个 1.5.x 发布号。
