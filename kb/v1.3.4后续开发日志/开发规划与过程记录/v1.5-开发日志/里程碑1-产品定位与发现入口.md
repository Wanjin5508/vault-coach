# 里程碑 1：产品定位与发现入口

## 1. 目标

先完成低风险、高收益的产品表达：Marketplace 搜索描述、README 第一屏和固定用户词汇。此阶段不声称内置 embedding 已完成；可以写成 1.5 预告或在功能完成后再切换最终文案。

学习重点：把技术能力翻译为用户结果、metadata 一致性、文档验收、发布渠道边界。

## 2. 用户结果词汇

| 内部技术                 | 默认用户文案                                           |
| -------------------- | ------------------------------------------------ |
| RAG                  | Ask questions about your notes                   |
| citation grounding   | Every answer links back to its source            |
| exam generation      | Turn notes into practice exams                   |
| semantic graph       | See how your concepts connect                    |
| mastery              | See what you know and what to review             |
| retrieval            | Find knowledge you forgot you had                |
| incremental indexing | Keep knowledge up to date automatically          |
| builtin embedding    | Semantic search with no separate embedding setup |

Developer docs 仍可使用 RRF、TopK、rerank 等术语。产品首页只在 Advanced/technical section 解释它们。

## 3. 涉及文件和外部位置

| 文件/位置                         | 修改                                |
| ----------------------------- | --------------------------------- |
| `manifest.json`               | description，正式发布时 version 由 M9 修改 |
| `package.json`                | description 与仓库定位同步               |
| `README.md`                   | Hero、故事式闭环、Quick start、隐私说明、截图顺序  |
| `README_CN.md`                | 中文等价表达，不逐字硬译                      |
| `assets/screenshots/`         | 最终补 4 步连续截图/GIF；不包含私人笔记/API key   |
| GitHub repository description | 手工同步；需要仓库权限，不由代码自动完成              |
| Obsidian community metadata   | 核对社区目录 description；按官方流程更新        |
| Forum/Discord/中文社区            | M9 发布后手工更新，不在本里程碑发送               |

官方社区目录使用 name、author、description 搜索，详情页读取仓库 manifest/README，安装读取同版本 Release assets。因此文案和版本必须分层核对：<https://github.com/obsidianmd/obsidian-releases>

## 4. 推荐信息结构

### 4.1 Marketplace description

候选：

> AI learning assistant that turns Obsidian notes and PDFs into cited answers, exams, knowledge graphs, and personalized mastery tracking.

验收问题：

1. 第一短语是否说明产品类别？
2. 是否包含普通用户会搜的 AI、learning、notes、PDF、exam？
3. 是否说明与普通 chat sidebar 的差异？
4. 是否没有承诺尚未交付的 zero setup？
5. 是否满足 manifest description 的长度和格式校验？

### 4.2 README 第一屏

```text
Logo + one-line promise
↓
Ask one question → cited answer
↓
Generate an exam
↓
Detect a weak concept
↓
Open it in Learning Map and review the source
↓
Install / Quick start / Privacy summary
```

第一屏不列 keyword/vector/RRF。技术架构放到后面的 “How retrieval works” 折叠或开发文档链接。

### 4.3 演示故事

使用一个非隐私、可重复的示例 Vault。例如 5 篇强化学习讲义：

1. Ask：“Why does PPO use clipping?”；
2. 展示来源卡片；
3. 生成 10 题考试；
4. 错答 TD Target；
5. Dashboard 显示需复习；
6. Learning Map 展示 TD → TD Target → TD Error → DQN；
7. 点击回到来源。

截图必须来自真实可运行功能。不要用设计稿暗示功能已实现。

## 5. 手动实施步骤

### Step 1：做文案 inventory

搜索当前 README/manifest 中的：

```bash
rg -n "RAG|retrieval|embedding|hybrid|rerank|knowledge graph|mastery" README.md README_CN.md manifest.json package.json
```

按“Hero / 用户功能 / Advanced / Developer”分类，不做全局机械替换。

### Step 2：先写英文结构，再写中文等价版

英文是 Marketplace 和国际社区入口；中文要保持同一事实边界。建立一张段落对照表，避免一边更新后另一边继续宣称旧流程。

### Step 3：更新 metadata

只改 description 时不要提前 bump version。用 JSON parser 验证，不手工留下尾逗号。

### Step 4：制作 screenshot shot list

为每张图列：目标、状态、Vault fixture、需隐藏信息、尺寸和 alt text。功能未完成前使用 placeholder 注释，不提交伪造截图。

### Step 5：做“5 秒测试”

让不了解 RAG 的读者只看 Hero 5 秒，然后回答：

- 它是什么？
- 输入是什么？
- 输出是什么？
- 为什么不是普通 AI chat？

记录误解并迭代。

## 6. 测试与检查

### 自动检查

- JSON 可解析；
- README 内部链接和图片路径存在；
- manifest/package 的产品定位不冲突；
- `npm run build` 仍通过；
- `git diff --check` 无空白错误。

可考虑新增 `scripts/check-doc-links.mjs`，只检查仓库内相对链接和图片，不在 CI 抓取全部外网链接。

### 手工检查

- Obsidian Community Plugins 搜索词：AI、learning、study、RAG、semantic、exam、knowledge graph、PDF；
- GitHub 桌面与移动宽度查看第一屏；
- 图片 alt text 可理解；
- README 没有 API key、个人路径、真实 Vault 文件名；
- dark/light theme 截图对比度可读。

## 7. 调试练习

1. 故意把一个图片路径改错，写脚本让 CI 捕获；
2. 故意让 manifest/package description 不一致，设计检查规则；
3. 在窄屏查看 Hero，定位 Markdown 表格或图片溢出；
4. 用 `git diff --word-diff` 审查文案变化，练习发现误删事实。

## 8. PR 切片

1. `docs: define v1.5 product vocabulary`；
2. `docs: rewrite README hero and learning-loop story`；
3. `chore: align manifest and package descriptions`；
4. `test: validate local README asset links`（若新增脚本）。

不要在同一 PR 加入 embedding 依赖或 UI 代码。
