# M6.2-A2：Qwen2.5 q4 候选验证开发日志

## 1. 本次目标与边界

本次从 q8 技术实验提交继续，验证同一不可变 revision 的 `q4` 是否能降低 Node CPU 资源占用，并保持 strict JSON 与最小语义诊断。分支为 `codex/m6-2-utility-slm-q4`。

边界保持不变：不接入 `LocalAIRuntime` 生产 Worker，不修改路由、设置或默认值，不写用户记忆，不做 fence 清理、JSON repair 或外部 provider fallback。

## 2. 实现记录

1. 在 `benchmarks/local-ai/models.json` 新增独立候选 `qwen2.5-0.5b-instruct-q4-utility`，不覆盖 q8 历史证据。
2. 复用 M6.2-A 的因果模型加载器、production strict validator、五例 smoke、输出哈希和无正文结果格式。
3. 使用已锁定的 `@huggingface/transformers@4.3.1` dtype 映射：`q4 → model_q4.onnx`。
4. 两次使用 `do_sample:false`、`num_beams:1` 独立加载并生成，比较五项 `outputSha256`。

## 5. 失败明细

| 样例 | contract | 语义诊断 |
| --- | --- | --- |
| zh coreference rewrite | PASS | PASS |
| en coreference rewrite | `invalid-json` | 无法进入语义诊断 |
| mixed negation rewrite | PASS | 丢失 WebGPU、离线与否定约束 |
| positive memory | PASS | 丢失 Germany/德国事实 |
| negative memory | `invalid-json` | 无法进入语义诊断 |

两次五项输出哈希完全一致，证明当前失败在锁定环境下可复现，不是随机采样波动。没有对无效输出做清理或二次请求。

## 6. Gate 决策

结论：**Qwen2.5-0.5B-Instruct q4 candidate NO-GO**。

- 下载：`797647451 > 629145600` bytes，FAIL。
- 资源：run-end RSS `1844–1891 > 1024` MiB，FAIL。
- strict schema：`3/5`，远低于建议的 98%，FAIL。
- 语义：仅 `1/5` 通过最小诊断，FAIL。
- Worker/Obsidian/目标设备：未执行；Node NO-GO 后不继续消耗集成成本。

q4 相比 q8 降低了部分 RSS，但同时扩大交付资产并恶化 contract/语义表现，不能作为资源降档方案。

## 7. 后续计划

下一步进入 **M6.2-A3 Candidate decision**，先做纸面与资产清单预筛，不立即下载：

1. 候选必须有 zh/en/de 或至少 zh/en 的明确证据，英文-only 模型只作 control。
2. 必须支持 WASM 可用的单一或可管理资产形态；WebGPU q4f16 不能替代 WASM Gate。
3. 先审许可证与授权 UX，再下载；Gemma 条款和 external-data 仍是显式阻塞项。
4. 预估资产超过 600 MiB 的候选直接淘汰。
5. 若没有候选能合理满足资源与语言约束，允许维持现有 external/disabled 路径并结束本版本内置 Utility 路线。
