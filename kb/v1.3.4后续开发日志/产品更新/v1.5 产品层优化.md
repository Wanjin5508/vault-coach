 接上文[[v1.4 产品分析]]得出下一阶段的产品原则：

> **默认情况下，用户不应该知道 embedding、chunk top-k、RRF、rerank 这些东西存在。用户只需要选择自己的知识范围，并配置一个 LLM，Vault Coach 就应该能工作。**

你当前代码里，Embedding 仍然直接依赖 Ollama `/api/embed`，设置页也把 Embedding model、Top-K、chunk 参数、rerank 等技术参数暴露给用户。 这在开发阶段很好，但到了产品阶段，我建议明确分成 **Default Experience** 和 **Advanced Settings**。

下面我把前面的 7 项全部展开成可以实际执行的方案。

# 4. 内置 Embedding：这是 1.5 最值得做的工程改造

这一项我建议真正做成 Vault Coach 1.5 的核心。

你当前：

```ts
embedTexts()
      ↓
Ollama /api/embed
```

也就是说向量检索仍然依赖外部运行时。

建议改成：

```text
AdvancedRagEngine
       │
       ▼
EmbeddingProvider
       │
 ┌─────┼────────────┐
 ▼     ▼            ▼
BuiltIn  Ollama   OpenAI-compatible
```

默认：

```text
BuiltIn
```

Ollama / API 则变为 Advanced Provider。

---

## 4.1 首先重构 Provider 接口

不要直接在 `LocalModelClient` 里继续堆判断。

建议新增：

```ts
interface EmbeddingProvider {
    embedTexts(texts: string[]): Promise<number[][]>;
    getModelId(): string;
    getDimension(): number | null;
}
```

然后：

```text
BuiltinEmbeddingProvider
OllamaEmbeddingProvider
OpenAIEmbeddingProvider
```

`AdvancedRagEngine` 不应该知道具体谁生成 embedding。

它只应该调用：

```ts
embeddingProvider.embedTexts(...)
```

这样以后：

WebGPU、Ollama、OpenAI、Voyage、Cohere

都不会污染 RAG Engine。

# 4.2 技术方案：Transformers.js

这个方向是完全可行的。

Transformers.js 官方支持直接在浏览器运行 `feature-extraction`，可以通过 WASM 在 CPU 上运行，也可以使用 WebGPU 加速。([Hugging Face](https://huggingface.co/docs/transformers.js/en/index?utm_source=chatgpt.com "Transformers.js · Hugging Face"))

典型流程就是：

```ts
pipeline(
    "feature-extraction",
    MODEL_ID
)
```

然后：

```text
text
 ↓
tokenizer
 ↓
ONNX model
 ↓
mean pooling
 ↓
normalize
 ↓
embedding[]
```

Transformers.js 官方也支持量化模型；在资源受限环境中，可以使用 q8/q4 减少带宽和内存。([Hugging Face](https://huggingface.co/docs/transformers.js/en/index?utm_source=chatgpt.com "Transformers.js · Hugging Face"))

# 4.3 默认模型怎么选

这里我不建议直接照抄 Smart Connections 的 `bge-micro-v2`。

Smart Connections 确实已经证明：

> Obsidian + 内置 Transformers embedding

这个产品方案是成立的，而且他们明确宣传“zero setup、本地 embedding、无需 API Key”。([GitHub](https://github.com/brianpetro/obsidian-smart-connections/blob/main/README.md?utm_source=chatgpt.com "obsidian-smart-connections/README.md at main · brianpetro/obsidian-smart-connections · GitHub"))

但 `bge-micro-v2` 是从 `BAAI/bge-small-en-v1.5` 蒸馏而来，本质偏英文。([Hugging Face](https://huggingface.co/SmartComponents/bge-micro-v2?utm_source=chatgpt.com "SmartComponents/bge-micro-v2 · Hugging Face"))

Vault Coach 面向 Obsidian 用户，而且你自己的用户场景明显可能出现：

```text
中文
English
Deutsch
```

因此我更建议 MVP 测试：

**`Xenova/paraphrase-multilingual-MiniLM-L12-v2`**

它已经提供 Transformers.js-compatible ONNX 模型，输出 384 维 embedding。([Hugging Face](https://huggingface.co/Xenova/paraphrase-multilingual-MiniLM-L12-v2?utm_source=chatgpt.com "Xenova/paraphrase-multilingual-MiniLM-L12-v2 · Hugging Face"))

它还有 int8/quantized ONNX 版本，单个 int8 模型文件约 118 MB；加 tokenizer 等资源，首次下载大致会是一百多 MB 量级。([Hugging Face](https://huggingface.co/Xenova/paraphrase-multilingual-MiniLM-L12-v2/tree/main/onnx "Xenova/paraphrase-multilingual-MiniLM-L12-v2 at main"))

这个体积对于：

> 一次下载 → 本地缓存 → 长期使用

是可以接受的。

不过正式决定之前，我建议拿真实 Vault 数据做一个小 benchmark：

```text
20 个中文 query
20 个英文 query
20 个德文 query

每个 query 人工标注 3–5 个 relevant chunks
```

比较：

```text
Recall@5
Recall@10
MRR
indexing speed
memory consumption
model download size
```

候选至少比较：

```text
paraphrase-multilingual-MiniLM-L12-v2
multilingual-e5-small
bge-micro-v2
```

最后不要追求 MTEB 最强，而应该选：

> **质量足够 + 下载小 + 内存低 + 手机上能跑。**

# 4.4 不要在 UI 主线程执行大量 Embedding

这是非常重要的工程点。

应该使用 Worker：

```text
Obsidian UI
     │
     │ batch texts
     ▼
Embedding Worker
     │
     ▼
Transformers.js
     │
     ▼
vectors
     │
     ▼
KnowledgeBase
```

否则第一次索引 1000 个 chunks 时：

> sidebar freeze

这个问题又会回来。

Transformers.js 生态本身也推荐重计算通过 Web Worker 离开主线程执行。([Hugging Face](https://huggingface.co/docs/transformers.js/integrations/vercel-ai-sdk?utm_source=chatgpt.com "Using Transformers.js with the Vercel AI SDK · Hugging Face"))

建议继续沿用你当前：

```text
batchSize = 16
```

再实测：

```text
8
16
32
```

# 4.5 WebGPU 只做优化，WASM 才是 fallback

不要设计：

```text
必须支持 WebGPU
```

应该设计：

```text
if WebGPU supported
    → WebGPU
else
    → WASM CPU
```

Transformers.js 官方明确说明 WebGPU 仍不是所有环境都完全可用，因此必须保留 fallback。([Hugging Face](https://huggingface.co/docs/transformers.js/guides/webgpu?utm_source=chatgpt.com "Running models on WebGPU · Hugging Face"))

另外，你当前 manifest 是：

```json
"isDesktopOnly": false
```

也就是说 Vault Coach 设计上仍支持移动端。

Obsidian 官方说明移动端没有 Node.js / Electron API。([Developer Documentation](https://docs.obsidian.md/Plugins/Getting%20started/Mobile%20development?utm_source=chatgpt.com "Mobile development - Developer Documentation"))

所以内置 embedding 尽量坚持：

> browser APIs + WASM/WebGPU

而不是：

> native Node ONNX runtime。

这样你才不会为了 embedding 把整个插件改成 desktop-only。

# 4.6 模型缓存

首次运行：

```text
Download model
↓
Cache model
↓
Reuse
```

不要每次打开 Obsidian 都重新下载。

UI 应显示：

```text
Local semantic model

paraphrase-multilingual-MiniLM
✓ Installed
≈ xxx MB
```

并提供：

```text
Clear local model
```

而不是暴露模型 URL。

Transformers.js 本身支持远程模型，也支持指定本地 model path，并可以关闭 remote model loading。([Hugging Face](https://huggingface.co/docs/transformers.js/custom_usage?utm_source=chatgpt.com "Use custom models · Hugging Face"))

以后如果你特别重视真正的 offline-first，还可以考虑：

> 第一次在线下载 → 写入插件缓存 → 后续完全离线。

# 4.7 索引 metadata 必须增加 Embedding Provider

现在你的 snapshot 已经记录 embedding model。

下一步应该变成：

```ts
embeddingFingerprint = {
    provider: "builtin",
    model: "...",
    revision: "...",
    dimension: 384,
    dtype: "q8"
}
```

因为：

```text

+
新模型 query vector
```

绝对不能混用。

一旦 fingerprint 变化：

```text

→ rebuild
```

而不是继续复用旧 embeddings。
