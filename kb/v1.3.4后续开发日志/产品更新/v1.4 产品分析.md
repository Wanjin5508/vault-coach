# Vault Coach 与高下载量 Obsidian AI/RAG 插件竞争分析

我查了当前 Obsidian 社区市场里的几类代表性产品，也重新看了 Vault Coach 现在的市场页。我的核心判断是：

**Vault Coach 下载量只有几百，并不能简单归因于“功能不如竞品”。恰恰相反，你现在的功能密度已经高于很多下载量几万甚至几十万的插件。真正的差距主要来自：进入市场时间、累计下载统计机制、产品切入点的普适性、首次使用摩擦、搜索曝光，以及历史分发中断。**

而且还有一个更重要的问题：**Vault Coach 现在实际上已经不是一个普通的“RAG 插件”了，而你仍然容易拿它和 RAG/LLM Chat 插件比较。** 从 1.4.x 开始，它更接近一个“基于个人知识库的学习系统”。

---

## 一、先纠正一个容易误判的数据：Downloads ≠ 用户数

截至我现在查询到的市场数据：

|插件|当前累计 Downloads|上线时间|Releases|
|---|--:|--:|--:|
|Copilot|≈ 2M|约 3 年|125|
|Smart Connections|≈ 1.2M|约 4 年|375|
|Text Generator|583k|约 5 年|208|
|Khoj|54k|约 5 年|173|
|BMO Chatbot|52k|约 4 年|54|
|SystemSculpt AI|37k|约 2 年|154|
|Open Connections|≈ 2k|约 8 个月|98|
|**Vault Coach**|**361**|**约 6 个月**|**19**|
|Vault Chat Agent|304|约 3 个月|21|

Vault Coach 今天的官方页显示 **1.4.1、361 downloads、19 releases、上线 6 个月**。([Obsidian Community](https://community.obsidian.md/plugins/vault-coach "Vault Coach - Obsidian Plugin"))

这里非常重要：Obsidian 的下载统计是 **GitHub release asset 跨版本累计下载**，而不是“361 个独立用户”。老用户更新插件，同样会继续增加下载次数。社区也有人专门要求增加“最近 30/60/90 天下载量”，原因就是现有累计数字严重偏向老插件。([forum.obsidian.md](https://forum.obsidian.md/t/add-recent-downloads-metric-to-community-plugins/110036?utm_source=chatgpt.com "Add \"Recent Downloads\" Metric to community plugins - Feature requests - Obsidian Forum"))

于是形成一个很强的复利：

> 用户多 → 更新版本 → 老用户更新 → Downloads 增长 → Popular 排名/社会证明更强 → 更多新用户 → 下一次更新又产生更多 downloads。

所以 **Copilot 2M : Vault Coach 361 不能解释为用户规模相差 5500 倍**。

另外，2026 年新出现的 Vault Chat Agent 上线 3 个月也只有约 304 downloads。([Obsidian Community](https://community.obsidian.md/plugins/vault-chat-agent "Vault Chat Agent - Obsidian Plugin"))

因此，**几百下载对于一个 2026 年才进入高度饱和 AI 插件市场的新产品，并不像表面看起来那么异常。**

# 二、真正值得研究的是：那些插件到底解决什么问题？

这部分比功能表重要得多。

## Smart Connections：解决的是“我记得写过，但找不到”

这是我认为最值得 Vault Coach 学习的产品。

它现在大约 **120 万下载**。市场页第一句话不是：

> embedding、RAG、vector database……

而是：

> “Find related notes and excerpts while writing.”

它进一步明确把用户痛点定义为：

> 笔记越来越多，重要想法沉没在大量笔记里，用户不断搜索、重读、重复劳动。

然后给出的解决办法极其简单：

**你打开一篇笔记 → 它自动告诉你哪些旧笔记和当前内容有关。**

甚至用户不需要提问。

Smart Connections 默认自带本地 embedding：

**Install → Enable → 自动索引 → 开始出现 related notes。**

不需要 API Key，不需要 Ollama，不需要选择 embedding model。官方甚至直接把卖点写成了 **Zero setup / No API key**。([Obsidian Community](https://community.obsidian.md/plugins/smart-connections "Smart Connections - Obsidian Plugin"))

所以它实际上解决的不是“向量检索问题”，而是：

**知识遗忘问题。**

对于 Obsidian 用户，这是极其普遍的需求。

100 篇笔记可能不需要。

500 篇以后开始需要。

2000 篇以后会越来越明显。

而且这个需求每天存在。

这就是非常典型的：

**高频 + 广泛 + 用户无需学习新工作流。**

这是它 120 万下载背后的产品逻辑。

---

## Copilot：解决的是“我已经有一个知识库，但还得自己干活”

Copilot 已经到了约 **200 万累计下载**。它现在甚至已经进一步从 RAG 转向 Agent。

它的价值主张是：

> Turn your second brain into a smart assistant that gets knowledge work done.

也就是说，它已经不满足于：

> “问你的 Vault 一个问题。”

而是：

> **让 AI 对 Vault 做工作。**

现在它可以运行 OpenCode、Claude Code、Codex，检查笔记、搜索资料、创建 Obsidian 文件、修改内容、组织知识，并持续执行多步任务。还提供 Projects、Skills、Commands、Quick Ask 等工作流。([Obsidian Community](https://community.obsidian.md/plugins/copilot "Copilot - Obsidian Plugin"))

用户真正的问题是：

> “为什么我已经把资料全放进 Obsidian 了，还要自己搜索、整理、写总结、创建文件？”

Copilot 的答案就是：

> **让 Agent 做。**

这带来一个重要变化：

普通 RAG：

**Vault → Retrieve → Answer**

Copilot：

**Vault → Understand → Plan → Act → Modify Vault**

所以 RAG 已经变成后台基础设施，而不再是产品本身。

这也是为什么现在继续宣传：

> Hybrid retrieval + rerank + query rewriting

越来越难吸引普通用户。

用户并不关心 rerank。

用户关心：

> “它能帮我完成什么？”

---

# 三、Text Generator：它甚至不需要 RAG，就拿到了 58 万下载

Text Generator 很值得研究，因为它说明了一个事实：

**产品成功程度和 AI 技术复杂度没有线性关系。**

它大约 58.3 万 downloads，上线约五年。([Obsidian Community](https://community.obsidian.md/plugins/obsidian-textgenerator-plugin "Text Generator - Obsidian Plugin"))

它主要解决：

> **写东西太麻烦。**

例如直接从笔记：

生成 idea、标题、摘要、outline、段落。

然后提供 prompt template。

所以用户可能每天：

写文章 → summarize；

开会 → extract actions；

写博客 → generate outline；

改文字 → rewrite。

它实际上是在解决：

**Blank page + 重复写作劳动。**

而且交互成本非常低：

> 选中文本 → AI → 得到结果。

这和“构建知识图谱”相比，用户教育成本几乎为零。

更重要的是，它建立了 **Community Templates**。

这样每个用户可以创造新的 use case，其他用户直接复用。([Obsidian Community](https://community.obsidian.md/plugins/obsidian-textgenerator-plugin "Text Generator - Obsidian Plugin"))

这实际上形成了产品增长机制：

**用户 → Template → 新使用场景 → 新用户。**

---

# 四、Khoj：解决的是“我的知识不只在 Obsidian”

Khoj 约 5 年、5.4 万 downloads。([Obsidian Community](https://community.obsidian.md/plugins/khoj "Khoj - Obsidian Plugin"))

它的问题定义要更大：

> 我的 Markdown、PDF、Word、Notion、Web 信息分散在不同地方。

所以 Khoj 提供：

**Personal AI / Second Brain。**

它可以搜索 Markdown、PDF、Word、Notion 等文档，也能搜索 Web，还支持：

Browser、Obsidian、Desktop、Phone、WhatsApp。

进一步支持：

Agent、自动研究、newsletter、semantic search。

([Obsidian Community](https://community.obsidian.md/plugins/khoj "Khoj - Obsidian Plugin"))

因此它卖的也不是 RAG。

它卖的是：

> **“我所有的信息，都可以通过同一个 AI 找到。”**

RAG 只是实现这个承诺的基础设施。

---

# 五、BMO Chatbot：解决的是“我就想在 Obsidian 里用 LLM”

BMO Chatbot 大约 5.2 万 downloads。

它技术目标其实比 Vault Coach 简单很多：

OpenAI / Anthropic / Gemini / Mistral / Ollama / LM Studio；

聊天；

引用当前 note；

在编辑器生成文字；

保存聊天记录。

([Obsidian Community](https://community.obsidian.md/plugins/bmo-chatbot?utm_source=chatgpt.com "BMO Chatbot - Obsidian Plugin"))

它解决的实际上是：

> **“我不想在 Obsidian 和 ChatGPT 浏览器窗口之间复制粘贴。”**

这是一个非常容易理解的问题。

安装插件之前用户就已经知道自己为什么需要它。

---

# 六、SystemSculpt：解决的是“AI 功能很多，但我不想配置一堆东西”

SystemSculpt 已经有约 **3.7 万 downloads**，上线约两年。

它把：

Agent Chat、semantic search、audio transcription、YouTube、Studio workflow 等功能放到一起。

但一个非常重要的产品设计是：

**用户不需要自己管理 provider key、model catalog 或本地 AI runtime。**

官方直接强调激活 license 后即可使用。([Obsidian Community](https://community.obsidian.md/plugins/systemsculpt-ai?utm_source=chatgpt.com "SystemSculpt AI - Obsidian Plugin"))

这说明另一个规律：

> AI 产品的配置成本，本身就是竞争力。

# 七、为什么 Vault Coach 当前增长慢？

把上面的竞品映射回来后，问题就比较清晰了。

## 1. 最大的结构性原因：进入市场太晚

Smart Connections 是四年前进入市场；

Copilot 三年前；

Text Generator 五年前。

它们基本经历了整个：

**GPT-3 → ChatGPT → RAG → Local LLM → Agent**

市场增长周期。

Vault Coach只有大约 6 个月。([Obsidian Community](https://community.obsidian.md/plugins/vault-coach "Vault Coach - Obsidian Plugin"))

更麻烦的是，现在已经有大量：

Chat with Vault；

RAG；

Semantic Search；

Ollama；

Agent；

AI Writing

插件。

所以如果 Vault Coach 只是：

> Another RAG plugin

它几乎没有增长空间。

好消息是，**1.4 已经让它脱离这个类别了。**

---

## 2. GitHub 封禁导致的分发中断确实产生了影响

这里我发现一个很值得注意的变化。

两周前搜索索引中的 Vault Coach 页面还显示：

> **334 downloads**
> 
> **This plugin has been archived and is no longer available.**

([Obsidian Community](https://community.obsidian.md/plugins/vault-coach?utm_source=chatgpt.com "Vault Coach - Obsidian Plugin"))

但我今天打开实时社区页，已经显示：

> **361 downloads**
> 
> Add to Obsidian
> 
> version 1.4.1

并且不再显示 archived。([Obsidian Community](https://community.obsidian.md/plugins/vault-coach "Vault Coach - Obsidian Plugin"))

所以你的插件最近显然已经重新恢复正常分发。

这意味着 GitHub 账号被封期间并不是单纯的“开发停滞”，而很可能造成了一段**市场目录可用性和增长链条的中断**。

对一个只有半年历史的新插件，这种损失比对成熟插件严重得多。

# 八、我认为 Vault Coach 现在最严重的问题：搜索定位

这个问题甚至可能比产品功能重要。

Obsidian 官方明确说明：

**社区插件搜索会使用 `name`、`author` 和 `description`。** ([GitHub](https://github.com/obsidianmd/obsidian-releases/blob/master/README.md?plain=1&utm_source=chatgpt.com "obsidian-releases/README.md at master · obsidianmd/obsidian-releases · GitHub"))

Vault Coach 当前 description 是：

> Build a reviewable knowledge graph from your Obsidian notes and PDFs. Explore concept relationships, ask cited questions, generate scoped exams, and track mastery through a Learning Map and dashboard.

([Obsidian Community](https://community.obsidian.md/plugins/vault-coach "Vault Coach - Obsidian Plugin"))

这个 description 产品表达其实已经不错。

但是有一个明显问题：

**里面没有这些核心搜索词：**

AI、LLM、RAG、semantic search、local AI、study assistant。

考虑一个第一次打开 Obsidian Community Plugins 的用户。

他大概率不会搜：

> reviewable knowledge graph

他更可能搜：

> AI

> ChatGPT

> LLM

> RAG

> semantic search

> study

> learning

而 Copilot 第一行就是：

**AI agents / Claude Code / Codex / OpenCode**。([Obsidian Community](https://community.obsidian.md/plugins/copilot "Copilot - Obsidian Plugin"))

Smart Connections 是：

**AI / embedding / semantic search / related notes / local**。([Obsidian Community](https://community.obsidian.md/plugins/smart-connections "Smart Connections - Obsidian Plugin"))

Khoj：

**AI personal assistant**。([Obsidian Community](https://community.obsidian.md/plugins/khoj "Khoj - Obsidian Plugin"))

Text Generator：

**GPT-3 / OpenAI**。([Obsidian Community](https://community.obsidian.md/plugins/obsidian-textgenerator-plugin "Text Generator - Obsidian Plugin"))

所以这里很可能存在真实的 SEO / marketplace search 损失。

例如描述可以考虑更接近：

> **AI learning assistant with cited RAG, semantic search, scoped exams, reviewable knowledge graphs, and mastery tracking for notes and PDFs.**

它没有改变定位，却把重要搜索入口全部补上了。

# 九、Vault Coach 的第二个增长障碍：Time-to-Value 太长

Smart Connections：

> Install → Enable → 看见 Related Notes。

Vault Coach 当前 Quick Start 实际是：

> Install → 设置知识库 → 选择 Markdown/PDF → 设置 PDF/chunk → rebuild index → 配置 chat provider → 配置 embedding provider → 验证 RAG → Ask → Exam → Concept Review → Learning Map → Dashboard。

官方 README 本身就是这样描述的。([Obsidian Community](https://community.obsidian.md/plugins/vault-coach "Vault Coach - Obsidian Plugin"))

从工程师角度，这套系统很完整。

从普通用户角度：

**还没体验到价值，已经做了很多配置。**

这就是典型的 Activation Problem。

尤其 Smart Connections 已经把标准提高到了：

> **Zero setup. No API key.**

([Obsidian Community](https://community.obsidian.md/plugins/smart-connections "Smart Connections - Obsidian Plugin"))

Open Connections 甚至也把 Transformers.js 本地 embedding 做成了默认路径，默认模型无需 API Key、不需要 Ollama，用户打开 note 后 related notes 自动出现。([Obsidian Community](https://community.obsidian.md/plugins/open-connections "Open Connections - Obsidian Plugin"))

这说明我认为 Vault Coach 后续非常值得考虑一个架构方向：

**增加内置轻量级 embedding runtime。**

例如 Transformers.js / ONNX / WebGPU/WASM。

哪怕质量不如用户自行部署的 BGE-M3，它也可以承担：

> 安装后的默认 semantic search / concept discovery。

而 Ollama / 云端 embedding 成为高级路径。

这会明显降低首次成功成本。

# 十、第三个问题：Vault Coach 解决的是“重要但非高频”的问题

Smart Connections 的价值每天都可能出现：

> “我之前写过什么相关内容？”

Text Generator：

> “帮我写。”

Copilot：

> “帮我做。”

Vault Coach 当前核心循环则是：

> Ask → Exam → Concept Review → Learning Map → Mastery。

而且你的 README 已经明确把这一循环描述出来了。([Obsidian Community](https://community.obsidian.md/plugins/vault-coach "Vault Coach - Obsidian Plugin"))

这实际上解决的是：

> **“我积累了很多知识，但不知道自己到底掌握了什么，也缺少系统复习。”**

这是一个很好的问题。

但它天然更适合：

学生、研究人员、证书考试、面试准备、长期专业学习。

而不是所有 Obsidian 用户。

所以你的 TAM 天然就比：

> AI writing

> semantic search

> related notes

小。

这不是产品错误。

反而意味着你应该**停止试图在“通用 AI 助手”赛道赢过 Copilot**。

# 十一、Vault Coach 真正应该占据的产品位置

我认为最重要的定位变化是：

### Smart Connections

**Remember what you wrote.**

### Copilot

**Let AI work on your vault.**

### Text Generator

**Write faster.**

### Khoj

**Ask your entire digital brain.**

### Vault Coach

**Learn what is in your vault — and know what you still don't know.**

这最后一句才是你的壁垒。

因为 Vault Coach 已经有一个竞品很少拥有的闭环：

```text
Notes / PDF
     ↓
Grounded RAG
     ↓
Exam
     ↓
Assessment Evidence
     ↓
Concept Graph
     ↓
Mastery
     ↓
Learning Map / Recommendation
     ↓
Next Exam
```

你的市场页已经在描述这个体系：考试可以限定 Vault/Folder/File；Concept Graph 中候选关系带 source evidence，需要确认；Mastery 来自真实 assessment，而不是“打开过笔记”这种弱信号；Dashboard 再基于这些 evidence 生成下一步建议。([Obsidian Community](https://community.obsidian.md/plugins/vault-coach "Vault Coach - Obsidian Plugin"))

**这一套明显比“Chat with your Vault”难复制得多。**

---

# 十二、为什么我反而认为 1.4 是 Vault Coach 真正的“产品 1.0”

早期 Vault Coach 本质上是：

> Local RAG + Exam。

用户看到以后很容易想到：

> “为什么不用 Copilot / Khoj / Smart Connections？”

现在则变成：

> **Knowledge → Assessment → Knowledge Graph → Mastery → Review**

它开始形成独特的数据飞轮。

一次考试不再只是一次 LLM 对话。

考试结果成为长期 evidence。

Concept 不再只是 embedding 得到的相似关系。

它可以经过 review。

Learning Map 也不再只是漂亮的 graph visualization。

它连接了掌握度。

这就是明显的产品差异化。

所以你现在的核心问题其实已经由：

> **“产品功能不够多。”**

变成：

> **“市场还不知道为什么需要这个产品。”**

|因素|对下载量影响|我的判断|

# 十四、接下来最值得做的不是继续堆功能

如果目标是把 **361 → 1,000 → 5,000**，我会优先做下面这一组，而不是立刻继续增加 RAG 算法复杂度：

1. **马上优化 marketplace description**，加入 AI / RAG / semantic search / learning 等用户真实搜索词。
    
2. **把首页第一屏改成一个极具体的故事**：`5 篇课程笔记 → 一键考试 → 找出薄弱 Concept → Learning Map 定位来源 → 再练习`。
    
3. **缩短 First Successful Experience**，最好第一次打开插件就能在几分钟内获得一个有意义的结果。
    
4. **考虑内置 embedding 模型**，把 Ollama/云 embedding 从“进入产品的门槛”变成“高级选项”。
    
5. **宣传时少说 Advanced RAG、RRF、rerank、ANN，多说结果**：`Find weak concepts`、`Turn notes into exams`、`See what you actually know`、`Every answer and concept is traceable to source`。
    
6. **把 RAG 当基础能力，把 Learning Loop 当产品。**
    
7. 用官方推荐渠道持续发布版本更新。Obsidian 官方本身就建议正式发布后在 Forum Showcase 和 Discord `#updates` 宣传。([GitHub](https://github.com/obsidianmd/obsidian-releases/blob/master/README.md?plain=1&utm_source=chatgpt.com "obsidian-releases/README.md at master · obsidianmd/obsidian-releases · GitHub"))

## 最关键的结论

如果 Vault Coach 现在还是 1.0 时代那个：

> “Local knowledge Q&A using RAG + Ollama”

那么我会认为它面对 Smart Connections、Copilot、Khoj，增长前景比较有限。

但现在的 **1.4.x 已经完全不是这个产品了**。

Smart Connections 帮用户解决的是：

> **“我的知识在哪里？”**

Copilot 解决：

> **“谁帮我处理这些知识？”**

而 Vault Coach 完全可以占据一个不同的位置：

> **“这些知识我到底掌握了多少？下一步应该学什么？”**

这其实是一个比“又一个 Obsidian RAG Chatbot”更清晰、也更有防御性的方向。

而目前 361 downloads 最大的问题，不是它证明了产品没人要。相反，结合上线只有 6 个月、下载统计机制、AI 插件赛道已经高度拥挤，以及中间发生过一次真实的分发中断，**现在的数据还远不足以否定产品本身**。目前更应该解决的是 **Discovery → Activation → Aha Moment → Retention** 这条增长漏斗，而不是继续追求 RAG 技术栈比竞品复杂。

如果下一步继续推进这个问题，我最建议做的是直接把 **Vault Coach、Smart Connections、Copilot、Khoj、Text Generator** 按照「用户画像—核心 Job to be Done—首次使用流程—留存机制—商业模式—Vault Coach 可以抄什么/不能抄什么」做成一张完整的竞品矩阵。这样基本就能进一步推导出 **Vault Coach 1.5 最应该做的产品改动和市场推广方案**。
