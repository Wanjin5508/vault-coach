# Vault Coach

> 语言版本：[English](./README.md) | 中文

Vault Coach 是一个运行在 [Obsidian](https://obsidian.md) 中的知识库问答插件。它会基于你的 Markdown 笔记构建可检索的知识库，通过 RAG（检索增强生成）从笔记中召回相关内容，再交给本地或用户配置的模型生成回答。

插件默认走本地 [Ollama](https://ollama.com)，也支持用户显式配置 OpenAI-compatible 的云端或自托管模型服务。

## 插件能力

Vault Coach 会扫描你的 Obsidian Markdown 文件，将笔记切分为 chunk，建立文本索引和可选的向量索引。每次提问时，它会检索相关笔记片段，并在回答下方展示可点击的引用来源。

主要功能：

- 混合检索：支持关键词检索、向量检索和 hybrid 融合检索。
- Query rewrite：回答前自动将用户问题改写为更适合检索的查询。
- Rerank：支持独立 rerank 服务；未配置时回退到本地启发式 rerank。
- 长期记忆：从对话中提取长期有用的信息，并在后续相关问题中注入。
- 自动增量同步：监听 Markdown 文件变化，自动同步索引。
- 真实流式输出：模型生成时逐步显示文本，完成后再渲染 Markdown。
- Markdown 来源渲染：回答来源中的摘录支持 Markdown 渲染，并可跳转回原笔记。
- 双语界面：插件界面和设置页会跟随系统语言显示中文或英文。
- 默认本地优先：默认使用 Ollama；只有用户明确配置后才会调用远程服务。

## 首次使用

启用插件后，可以通过左侧 ribbon 图标或命令面板打开 Vault Coach 侧边栏。首次提问前，建议先进入 **设置 → Vault Coach** 检查知识库范围和模型配置。

推荐的首次配置顺序：

1. 在 **知识库** 中选择扫描整个 vault，或只扫描某个指定目录。
2. 在 **模型** 中确认回答模型服务和 embedding 模型服务。默认推荐使用 **本地 Ollama**。
3. 填写本地聊天模型和本地 embedding 模型，确保这些模型已经存在于 Ollama 中。
4. 在侧边栏点击 **重建索引**，或等待文件变化触发自动同步。
5. 在侧边栏输入问题开始问答。

第一次提问可能会更慢，因为插件可能需要建立文本索引、生成或刷新 embedding、执行检索，并调用模型。进入最终回答生成阶段后，Vault Coach 会以流式方式逐步显示文本，完整回答生成后再渲染为 Markdown。

## 设置说明

设置页的顺序与插件当前界面保持一致：**基础 → 知识库 → 模型 → 长期记忆 → 高级 RAG**。

### 基础

这一部分控制侧边栏显示、启动行为和会话默认值。

| 设置项 | 作用 | 建议 |
|--------|------|------|
| 助手名称 | 显示在侧边栏头部和助手消息中的名称。 | 一般保持默认即可。 |
| 默认欢迎语 | 重置会话时显示的第一条助手消息，支持 Markdown。 | 如果保持内置默认值，会跟随系统语言变化；自定义内容不会被覆盖。 |
| 启动时自动打开右侧边栏 | Obsidian 启动后自动打开 Vault Coach。 | 如果不想每次启动都打开插件，可以关闭。 |
| 默认检索模式 | 侧边栏打开时默认使用 keyword、vector 或 hybrid。 | 大多数场景推荐 hybrid。 |
| 来源默认折叠 | 控制回答下方的来源区域是否默认折叠。 | 想让聊天界面更清爽就开启；经常核对来源就关闭。 |

### 知识库

这一部分决定哪些笔记进入索引，以及 Markdown 内容如何切块。

| 设置项 | 默认值 | 作用 | 建议 |
|--------|--------|------|------|
| 扫描范围 | 整个 vault | 控制索引整个 vault，还是只索引指定目录。 | 如果只想问某个项目或专题，建议选择指定目录。 |
| 指定目录 | 空 | 扫描范围为指定目录时使用的路径。 | 填写 vault 内相对路径，例如 `知识库/RAG`。 |
| Chunk 大小 | 600 | 每个片段允许的最大字符数。 | 越大上下文越完整，但 embedding 和生成开销也更高。 |
| Chunk 重叠 | 120 | 相邻 chunk 之间保留的字符数。 | 保留一定重叠可以减少切块边界造成的信息损失。 |
| 启用自动增量同步 | 开启 | 监听 Markdown 文件变化并自动同步索引。 | 日常使用建议开启。 |
| 自动同步文件阈值 | 8 | 累计变更文件达到该数量时立即同步。 | 调低会更及时，调高会减少后台工作。 |
| 自动同步防抖时间 | 15,000 ms | 最后一次文件变化后等待多久再同步。 | 如果经常连续编辑多篇笔记，可以适当调大。 |
| 自动同步最大等待时间 | 120,000 ms | 文件变化持续发生时，最长等待多久后强制同步。 | 用于避免长时间编辑导致索引迟迟不同步。 |

修改扫描范围、chunk 参数或 embedding 配置后，知识库会被标记为需要重建。要让检索结果反映新配置，请在侧边栏点击 **重建索引**。

### 模型

这一部分决定回答生成、向量检索和可选 rerank 分别调用哪个服务。只有当前被选中的服务会被调用。

#### 回答模型服务

回答模型用于 query rewrite、最终回答生成和长期记忆抽取。

| 选项 | 含义 | 需要配置 |
|------|------|----------|
| 本地 Ollama | 调用本地 Ollama 聊天接口。 | 本地推理服务地址、本地聊天模型。 |
| OpenAI 兼容 | 调用用户配置的云端或自托管 OpenAI-compatible 聊天接口。 | 云端聊天服务地址、云端聊天模型、云端密钥。 |

如果使用 Ollama，本地推理服务地址通常填写 `http://127.0.0.1:11434`。不要在地址后面追加 `/api/chat`。

如果使用 OpenAI-compatible 服务，可以填写服务根地址或 `/v1` 地址。Vault Coach 会在需要时自动拼接 `/chat/completions`。

#### Embedding 模型服务

Embedding 模型用于向量检索。切换 embedding 服务或模型后，需要重建索引，因为旧向量和新模型不再匹配。

| 选项 | 含义 | 需要配置 |
|------|------|----------|
| 本地 Ollama | 调用本地 Ollama embedding 接口。 | 本地推理服务地址、本地 embedding 模型。 |
| OpenAI 兼容 | 调用用户配置的云端或自托管 embedding 接口。 | 云端 embedding 服务地址、云端 embedding 模型、云端密钥。 |

使用云端 embedding 时，构建向量索引可能会向远程服务发送大量笔记 chunk。只有在理解并接受这种数据流向后，才建议启用云端 embedding。

#### 云端密钥

Vault Coach 只会在插件设置中保存 Obsidian SecretStorage 条目的名称，不应该把原始 API key 保存到 `data.json` 中。

#### 可选 Rerank 服务

Rerank 是可选能力。如果 **独立 rerank 服务地址** 或 **Rerank 模型** 为空，插件会自动回退到本地启发式 rerank。

| 设置项 | 作用 |
|--------|------|
| 独立 rerank 服务地址 | 可选的 rerank endpoint，通常是兼容 `/v1/rerank` 的服务。 |
| Rerank 模型 | rerank 服务使用的模型名称。 |

### 长期记忆

长期记忆会从历史对话中提取对未来仍有价值的信息，并在后续相关问题中注入。

| 设置项 | 默认值 | 作用 | 建议 |
|--------|--------|------|------|
| 启用长期记忆 | 开启 | 是否抽取并使用长期记忆。 | 如果希望每轮对话相互独立，可以关闭。 |
| 记忆注入数量 | 4 | 每次回答最多注入多少条相关记忆。 | 建议保持较低，避免干扰当前问题。 |
| 最大记忆条数 | 150 | 本地最多保留多少条长期记忆。 | 只有大量依赖跨会话上下文时才需要调高。 |
| 最大持久化消息数 | 60 | 本地保存多少条对话历史。 | 数值越高，状态文件越大。 |

### 高级 RAG

这一部分控制检索质量、候选数量和最终注入 prompt 的上下文规模。默认值偏保守，适合多数用户。

| 设置项 | 默认值 | 作用 | 建议 |
|--------|--------|------|------|
| 启用 query rewrite | 开启 | 提问后先将问题改写为更适合检索的查询。 | 除非你的笔记场景中改写效果不好，否则建议开启。 |
| 启用向量检索 | 开启 | 重建索引时生成 embedding，并启用 vector / hybrid 模式。 | 如果无法使用 embedding，或只想关键词检索，可以关闭。 |
| 启用 rerank | 开启 | 对召回候选进行重排。 | 建议开启，有助于让更相关的来源排在前面。 |
| 关键词 top k | 10 | 关键词召回保留的候选数量。 | 查询较宽泛时可以适当调高。 |
| 向量 top k | 10 | 向量召回保留的候选数量。 | 调高可增加语义召回，但会增加后续处理量。 |
| Hybrid 候选上限 | 12 | 关键词和向量融合后保留的候选数量。 | 检索经常漏内容时可以适当调高。 |
| Rerank top k | 8 | 进入 rerank 阶段的候选数量。 | 值越大，潜在召回更全，但处理更慢。 |
| 上下文 chunks 数 | 8 | 最终注入 prompt 的 chunk 数量。 | 不是越多越好，太多会稀释重点。 |
| 来源数量上限 | 5 | 每条回答下方展示多少条来源。 | 想查看更多引用时可以调高。 |
| 生成温度 | 0.2 | 控制回答随机性。 | RAG 问答通常建议保持较低。 |

## 侧边栏操作

侧边栏顶部会以网格形式展示当前知识库范围、文本索引状态、向量索引状态、文件数、片段数和长期记忆数量。

- **问答模式 / 考试模式**：目前是前端模式开关。当前实际生效的是问答模式，考试模式的后台逻辑尚未实现。
- **检索模式**：切换当前会话使用关键词、向量或混合检索。
- **重建索引**：重建文本索引，并在开启向量检索时重建向量索引。
- **重置会话**：清空当前对话历史，回到默认欢迎语。

## 隐私与网络使用

Vault Coach 默认本地优先。使用默认 Ollama 配置时，聊天和 embedding 请求只会发送到用户配置的本地 Ollama endpoint，通常是 `http://127.0.0.1:11434`。

只有当用户显式选择 OpenAI-compatible 的回答模型服务或 embedding 模型服务，并配置对应 endpoint、模型和 API key 后，插件才会发起远程请求。

启用远程回答模型时，远程服务可能接收到：

- 用户当前问题。
- RAG 回答所需的已检索 Markdown 片段。
- 少量最近对话上下文。
- 如果启用了长期记忆，则包含与当前问题相关的长期记忆。
- 模型名称、temperature 等参数。

启用远程 embedding 时，构建或刷新向量索引可能会向远程服务发送 Markdown chunk。

Vault Coach 不包含隐藏遥测。插件无法控制用户选择的远程服务如何保存或处理提交数据；启用远程服务前，请先确认对应服务商的隐私政策和数据保留政策。

## 当前限制

- 流式输出期间先显示纯文本；完整答案生成后，再使用 Obsidian MarkdownRenderer 渲染 Markdown。
- 来源摘录支持 Markdown 渲染，但如果截断摘录中包含 Mermaid 代码块，会作为普通文本渲染，以避免 Obsidian Mermaid 报错。
- 长期记忆检索目前基于关键词匹配，还不是语义相似度检索。
- 考试模式目前只是 UI 开关，后台考试逻辑尚未实现。
